# Jev call — jev-plan-exit (effectiveness-review)

_Per-call definition from jev-call-template.md. Built 2026-11-14 (phase-guard augmentation pass 1). The Plan→Execute gate for the lane's verdict job. This job's founding risk is named in its own register: SOFTENED-CEREMONY — a verdict (or a plan) whose headline is edited by politeness. That failure is cheapest to commit at Plan time, in what the plan quietly decides not to check, so the plan is judged before the verdict act begins._

## 1. What it judges
- Deliverable / surface judged: the cycle's Plan as recorded in RUN.md — the verdict plan per asset class, the cold-pull test design, the Execute checklist, the Verify checklist, and the failure-point evaluation — judged together with the Observe working memory and jev-observe-exit's filed profile (including any ADVANCE-WITH-GAPS limitations, which bind this plan).
- OPEVC call point: effectiveness-review INSTRUCTION §2 Plan, gate out. The phase advances on the verdict's recorded disposition (applied, or set aside with reason). An unfired call makes the cycle INCOMPLETE.

## 2. Instruction (the model's charge)
Judge whether this plan, executed exactly as written, would produce verdicts the evidence earns — no softer, no harder. Price, in order:
(1) CLASS COMPLETENESS — does the verdict plan name all five standing classes (technique catalogue · markdown assets · recreations · packets/read layer · the lane's growth reporting itself), each with the evidence lines it will be priced from? A class dropped from the plan is a verdict silently not filed; a class added without a priced reason is scope drift.
(2) THE SOFTENED-CEREMONY CHECK (founding risk, priced first among failure modes) — does anything in the plan pre-decide a milder outcome than the evidence path allows: a class pre-assigned USABLE-UNUSED before its clock is computed · a CEREMONY test removed or weakened for a class the lane favors · the headline rule (a CEREMONY verdict leads the HQ report) absent from the Verify checklist · production counts planned as the report's lead where consumption is the question? A plan that arranges not to find CEREMONY is the defect in its earliest, cheapest form.
(3) CLOCK PER CLASS — does the plan compute, per class, the elapsed unconsumed time against the verdict clock (started 2026-11-13) and name the date by which continued zero becomes CEREMONY evidence for that class (INSTRUCTION §3/§4's USABLE-UNUSED form)? A plan with no per-class clock cannot distinguish patience from ceremony.
(4) EXECUTE CHECKLIST — is there a concrete Execute checklist (named location: RUN.md Plan section): evidence re-count from sources (never from GROWTH.md's own figures — §5 guard 4) · citation spot-checks · cold-pull test run + timing · per-class verdict drafting with evidence lines · cure routing to owning jobs via the lane board for every CEREMONY · the self-application step (did the previous cycle's verdicts produce action anywhere — no cure filed, no board movement, no HQ response = a finding on this job itself, in the same verdict form)?
(5) VERIFY CHECKLIST — does it name instruments, not intentions, for each deliverable property: counts re-counted (command/guard named — mechanical guard 1) · USED claims each tied to a spot-checked CONSUMPTION row (mechanical guard 2) · self-edit quarantine census at close (mechanical guard 3) · jev-verdict fired on the draft report before filing (its verdict disposed on the record) · headline rule check (CEREMONY, if any, is line one of the HQ report) · verdict-history updated with the filed set? A Verify item that says "check quality" without naming what is run or read fails this dimension.
(6) FAILURE POINTS EVALUATED — does the plan name what breaks it, priced for this job: consumption still zero at the clock date (the verdict set is then ceilinged at USABLE-UNUSED / CEREMONY — planned for, not discovered) · the cold-pull test cannot be staffed with a genuinely fresh reader (test deferred = usability evidence absent = no USED/USABLE upgrade may lean on it) · a judged face changed mid-cycle by its owning job (evidence moves under the verdict — re-read or name the race) · jev-verdict not fired at filing time (the cycle then prints INCOMPLETE; the draft files under the manual panel, printed as such — never silently as guarded) · the observe-exit gaps binding this plan (each limitation either honored in the plan or explicitly overridden with reason).
(7) REDUCTIONS NAMED — anything the plan quietly drops from the OBJECTIVE (a class, the pull test, the self-application leg, a cure routing) is listed as a reduction with its reason, or the plan is hiding it.
Score 0–1 per dimension and classify defects. You judge the plan's honesty and completeness, never the lane and never the eventual verdicts.

## 3. Context contract (masked view)
- FED: the Plan record (RUN.md Plan section: verdict plan per class · cold-pull test design · Execute checklist · Verify checklist · failure-point evaluation) · the evidence table from Observe · jev-observe-exit's filed profile for this cycle · the standing class list + clock record · the previous cycle's verdict-history block (for the self-application step's presence only).
- NEVER FED: this job's rationale prose about the lane · draft verdict language (the plan is judged, not the verdict — verdict wording is jev-verdict's surface) · HQ's preferred outcome for any class · the lane's production self-congratulation (counts enter only as the evidence table states them).
- Context ceiling: ≤32,000 tokens of text. Packing rule: plan + evidence table + observe-exit profile fed whole; verdict-history fed as the single previous block only; overflow fails preflight, never truncates silently.

## 4. Output space
- Verdict classes: **EXECUTE** (the verdict act may begin) · **REVISE** (plan defects named; Plan re-opens, Execute does not) · **RETURN-TO-OBSERVE** (the plan exposes that the evidence base cannot support it — e.g. a class priced from a face Observe never read).
- Dimensional scores (0–1): class completeness · softened-ceremony resistance · clock explicitness · execute-checklist completeness · verify-instrument specificity · failure-point honesty. (1.0 = all five classes planned with evidence lines / no pre-softening anywhere and the headline rule in the Verify checklist / a computed clock + CEREMONY date per class / every §3/§4 act present as a checkable step / every Verify item naming its instrument or guard / every failure point in §2(6) that applies is named with its consequence. 0.0 = the opposite pole on each.)
- Rejection classification (one primary, on REVISE / RETURN-TO-OBSERVE; secondary findings may name passage + evidence): SOFTENED-CEREMONY-PLAN (the plan pre-decides or arranges a milder outcome — the founding risk) · MISSING-CLASS-PLAN (a standing class absent from the verdict plan) · NO-CLOCK (no per-class elapsed time / CEREMONY date) · CHECKLIST-VAGUE (an Execute or Verify item with no instrument, source, or guard named) · NO-SELF-APPLICATION (the previous cycle's action check missing from the plan) · REDUCED-VERDICT (the plan drops the pull test, a cure routing, or another OBJECTIVE element without naming it as a reduction) · GAP-UNBOUND (an observe-exit ADVANCE-WITH-GAPS limitation neither honored nor overridden with reason).
- Accepted profiles travel: the profile files in RUN.md beside the plan; its named failure points become Verify's watch list for the cycle, and jev-verdict receives the profile with the draft report.

## 5. Floors and disposition
- SOFTENED-CEREMONY-PLAN detected → REVISE at best; the plan may not EXECUTE until the softening is removed and the revised plan is rejudged (a rejudged plan is a new receipt; the old one is void).
- class completeness < 1.0 (any standing class missing) → REVISE.
- verify-instrument specificity < 0.5 → REVISE (a verdict act whose checks are intentions cannot be verified, only performed).
- softened-ceremony resistance < 0.5 → REVISE.
- RETURN-TO-OBSERVE is mandatory where the plan prices a class from evidence Observe never gathered.
- Disposition: the verdict is advisory — reviewed by the runner, applied or set aside with the miss recorded in Condense. The verdict + primary classification + disposition land in RUN.md either way, never a silent workaround.

## Call command
- Assemble the §3 context packet (text only, ≤32k, preflight-checked) and fire this file's §2 instruction against it via the fleet's sealed decision-model route — the same transport jev-verdict binds to; until that binding lands, the call is executed as this defined prompt + context assembly by the cycle runner and its receipt (packet identity · definition version · validated output · disposition) is filed in RUN.md. Malformed output = PROTOCOL FAILURE, recorded as a REVISE disposition, never an improvised verdict.
- Firing: this call fires at its step on every cycle. A cycle in which it did not fire prints INCOMPLETE.

## 6. Firing record and improvement
- Exemplars: (a) a plan covering all five classes with per-class clocks, a timed cold-pull design (fresh reader · 3-minute bar), instrument-named checklists, and the self-application step must receive EXECUTE. (b) A constructed plan identical to (a) except the growth-reporting class is pre-assigned USABLE-UNUSED "to keep the headline balanced" must receive REVISE / SOFTENED-CEREMONY-PLAN. (c) A constructed plan omitting the packets/read-layer class must receive REVISE / MISSING-CLASS-PLAN. (d) A constructed plan whose Verify checklist reads "verify all verdicts are fair" must receive REVISE / CHECKLIST-VAGUE.
- Firing: this call fires at its step on every cycle; its firing record and misses are its improvement material. No test precedes firing. The exemplars above stand as its first firing cases — all four must classify correctly when fired, and a miss is recorded in Condense as improvement material, never as a bar to firing.

## 7. Iteration (Condense)
This file is one of the four layers Condense iterates. Every amendment names: the evidence that forced it (a filed verdict later shown softer than its evidence — traced back to a plan this gate passed · a failure point that materialized unnamed) · before/after. A text change takes effect on the call's next firing; the call keeps firing every cycle, and Condense prices the change against the returns that follow it.
