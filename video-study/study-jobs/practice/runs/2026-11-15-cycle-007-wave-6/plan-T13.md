### F1 [C1 · Execute §2 · Verify §2 — canvas-measurement authority limits] — APPLIED
Plan amendments:
- **Font readiness:** canvas measurement runs with the exact configured font string (weight/size/family from the layout tokens). If `document.fonts` exists and the configured font is not yet loaded (`document.fonts.check` false), the measurement is classified UNCERTAIN, never "measured"; validation treats an uncertain title/chrome fit as a failure (see rejection rule below), and the build record prints the classification per element class.
- **Whitespace:** measurement input is normalized exactly as CSS `white-space: normal` renders it — runs of whitespace collapse to one space, leading/trailing whitespace at line edges is dropped — before word splitting.
- **Long-word breaking:** the wrap simulation follows `overflow-wrap: break-word`: a word wider than the line is broken at grapheme boundaries to fill lines; a word that fits moves whole to the next line. No other breaking is simulated.
- **Letter spacing:** any configured letter-spacing token on a measured element adds `spacing × (graphemes − 1)` to that element's measured width (titles carry 0; the stamp and any spaced chrome carry their token).
- **Marked-span padding at line breaks:** the highlighted span's horizontal padding is charged once per line fragment the span occupies (CSS fragments a padded inline per line box), and its radius does not reduce the charged width; a marked span crossing a break therefore costs padding on both fragments.
- **Rounding:** every measured width is rounded UP to 0.01px and a 1px-per-line epsilon is added before any comparison; a fit that only closes inside the epsilon does not close.
- **Feasibility valve instrument (named, runnable):** `t13-feasibility-instrument.js` (Node, written for this attempt, path + sha recorded in build-record-attempt3.md) — it extracts the fitting functions from the built source and runs the 360px budget (six specimen titles + joint header rows, 2-line bound, type floors) under BOTH the canvas-shaped interface (stubbed measurer fed by the estimate table, labelled as such) and the fallback table, printing PASS/FAIL per line. Execute step 2 runs it BEFORE the build is finalized; a FAIL stops per F7's split rule.
- **Fallback rule (replaces any upper-bound claim):** the fallback per-character-class width table is an ESTIMATE with NO upper-bound guarantee — the words "measurement", "worst-case" and "upper bound" are never printed for it. Uncertainty/rejection rule: on the estimate path, an element is accepted only if its estimated width is ≤90% of its available bound; an element estimated in the top 10% band below the bound, or above it, is REJECTED with the named outcome `T13_FIT_UNCERTAIN` (fail-closed), because the estimate cannot distinguish fit from overflow inside that band.
