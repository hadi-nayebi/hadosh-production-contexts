## 1. Cure plan — convergent order (A1: multi-lens findings first), each cure → named construction change

### Stage R — Readability (binding lens; convergent R×Reuse×Purity on literals, R×Timing on sweep)

- **R1 — Secondary-text sizes at 360px, perspective priced (READABILITY head cure).** Construction: raise the CONFIG typography floors for secondary text AND re-derive them THROUGH the perspective transform, not before it: chat body floor 11.16px → target ≥13px effective; sender/time (meta) floor 9px → ≥11px effective; stat labels 9px → ≥11px effective; stat values hold ≥14px. "Effective" = modelled size AFTER `perspective(900px) rotateX(2deg)` foreshortening at the element's screen position AND after framing scale 0.95–1.04 (worst framing priced, not the mean). Secondary opacity 0.75 → CONFIG-driven, raised (≥0.9) or compensated in the size/weight derivation — opacity is part of the legibility price, not a free aesthetic. Fit is re-verified after the raise (see R3 + Verify V-R1): larger chat text grows accumulated chat height, so R1 ships only with the vertical-containment model in R3b green. This is a CONSTRUCTION-FAMILY change for the secondary-text surface (size derivation through the transform + opacity in CONFIG), not a clamp re-tune — see §3 A-C011-3 finding.
- **R2 — Proportional-glyph-width sweep thresholds (cures the dark-before-covered defect).** Construction: replace the character-count threshold in `charColor` (`progress * charCount > charIndex`) with cumulative proportional glyph widths: each character's darkening threshold = (sum of advance widths of characters up to and including it) ÷ (total word advance width), widths from a CONFIG glyph-width table (per-character advance ratios for the title font stack, with a stated fallback ratio for unlisted glyphs) — a character turns dark only when bar progress ≥ its own right-edge fraction. The bar-coverage model and the colour model then share one width basis. Suite asserts per-character thresholds on words with deliberately unequal glyph widths (e.g. a word mixing narrow `I`/`l` and wide `M`/`W`): no character dark at progress below its right-edge fraction − epsilon; all dark at 1.0.
- **R3 — Framing clamp on MEASURED text bounds (two parts).** (a) Translation arithmetic: the clamp model must compute the displayed bounds exactly as CSS does — `scale(s) translate(x%, y%)` scales the translation — i.e. model `displayed = scale × (rect + translate)` in the same order the source composes it, and assert the modelled bounds against that composition for all 7 framings (initial + 6 cuts + loop boundary). (b) Measured bounds, not a declared rectangle: the clamped rectangle is derived from measured content — title lines at their CONFIG sizes with proportional widths (same table as R2), chat rows at their accumulated heights for the CURRENT message set, stat wrap, counter — at each framing's hold state; PLUS the vertical leg the attempt-2 return added: accumulated chat height vs screen height at a DECLARED viewport height (state the height in the build record; width-only containment does not satisfy this cure), with `#screen` clipping priced as a containment failure, not ignored. Any framing whose measured bounds exceed the stage is clamped or the record is rejected — no silent crop.
