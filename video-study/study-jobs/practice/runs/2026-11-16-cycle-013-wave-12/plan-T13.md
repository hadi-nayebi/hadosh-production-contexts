## 1. Cure plan (convergent-lens order first, per INSTRUCTION §2.2 / Amendment A1; then blocking lens, then ascending lens)

### ★ The A-C011-3 construction-family change (named concretely — this replaces what)

**OLD family (attempts 2–4, now retired for the fitting surface):** a *single-scalar proxy model* —
one `cqwPx = stageWidthPx / 100` derived from the stage's full (border-box) width converts every
token; fitting is validated at two nominal reference widths (360 / 1916); CONFIG consumption is
proven by *variable assignment* (a token set as a CSS var counts as consumed); whitespace is
normalized by JavaScript `\s` rules in the fitting path only.

**NEW family (attempt 5):** a *CSS-cascade-faithful displayed-state model* —
1. **Basis-resolved units:** every length conversion carries (value, unit, **basis box**). The cqw
   basis is the stage's **content-box inline size** (the box CSS resolves descendant cqw against),
   derived per mode from stage width, `box-sizing:border-box`, and the stage's own padding; % bases
   are named per property; px is absolute. The build record prints the A-C012-1 basis table
   (unit → basis box → rendered consequence at 360px) and the suite asserts it (R1).
2. **Displayed-effect consumption:** a CONFIG token counts as consumed only when mutating it changes
   the **computed displayed state of the element it names** (stylesheet rule present AND model
   effect AND rendered-style effect in the stub) — assignment alone fails the census (R2).
3. **Actual-viewport validation:** fitting/floor validation runs at the **actual stage width**
   (runtime `clientWidth`, re-run on resize) over a stated supported-width set, not at two nominal
   references (R4).
4. **One canonical text sequence:** fitting, validation, and playback all segment the **same**
   CSS-whitespace-collapsed sequence; there is no second, divergent sequence anywhere (R5).

This is a family change, not a re-tune: the model's basis object, its consumption criterion, its
validation widths, and its text sequence all change kind. The R1 token raise that rides on it is a
consequence of the corrected basis, not the cure itself.

### Reusability 64 — the blocking lens (single-lens cures, in the residual inventory's order)

**R3 — Unit-complete backstop/height validation** *(reusability 64)*
Construction:
- `--titleMaxH` backstop: `applyLayout()` currently computes
  `(maxTitleLines × cqwOf(titleFont) × titleLineHeight) + "cqw"` — it appends `cqw` to the numeric
  part of `titleFont` **regardless of the token's unit** (a `20px` title font yields a `50cqw`
  backstop). Replace with unit-preserving scaling (`scaledToken(titleFont, maxTitleLines ×
  titleLineHeight)`), so the backstop is denominated in the token's own unit end-to-end.
- Available-height calculation: `availCqw` currently reads `commentsTop`/`commentsBottom` through
  `cqwOf()` — treating them as percentages of stage height **regardless of unit**. Replace with
  `lenPx()` conversions against the named stage-height reference, in each token's own unit.
- `lenPx()` silent fallback: an unsupported unit (em/rem/vw/…) currently returns the bare numeric
  value as px while CSS interprets it differently. Replace with a **named fail-closed error**
  (`T13_UNIT_UNSUPPORTED:<token>`) raised in validation; the suite's adversarial set (A-C011-2)
  feeds em/rem/vw/empty-unit tokens and asserts the named error, never a silent number.

**R4 (reusability part) — Actual-viewport fitting + tallest-header card height** *(reusability 64)*
Construction:
- Validation widths: `validateConfig()` currently models only the two aspect-reference widths
  (1916 / 360). Replace with the **supported-width set {360, 390, 1916} plus the actual runtime
  width**: `modelFor()` runs at the stage's real `clientWidth` on load and on resize
  (re-validation on resize; a resize into an unsupported fit surfaces the named freeze, per the
  A-C011-2 resize-recompute class). Fixed-pixel geometry in a swap can no longer validate at a
  reference width while failing on the phone in hand.
- Card height: `cardHeightCqw()` prices the header row as the avatar's height alone. Replace with
  **tallest-header sizing**: header height = max(avatarSize, headFont × headLineHeight, badgeFont
  × badge line height + 2 × badgePadY) — each term in its own unit on the R1 basis — so a swap with
  taller text/badge geometry cannot under-price the stack and overflow silently.

**R5 — Identical whitespace sequences for fitting and playback** *(reusability 64)*
Construction: one canonical sequence function, consumed by BOTH paths:
- Define the canonical sequence by **CSS whitespace rules**: collapsible characters are exactly
  space / tab / LF / CR / FF; **nonbreaking space (U+00A0) is preserved** as a non-breaking word
  character (JavaScript `\s` collapses it; CSS does not — the attempt-4 divergence).
- `fitLines()` segments the canonical sequence; `renderTitle()`/schedule grapheme counts segment
  the **same** canonical sequence (today fitting segments the normalized text while playback
  segments the raw text, so grapheme indices — including the marked range — can diverge).
- The marked range is computed once, on the canonical sequence, and shared. Suite: a title
  containing NBSP + repeated spaces + a highlight asserts fitting graphemes === playback
  graphemes (sequence-equal, not count-equal) and identical mark indices in both paths.
