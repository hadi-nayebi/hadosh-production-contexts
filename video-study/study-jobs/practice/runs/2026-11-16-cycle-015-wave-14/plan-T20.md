## 2 — Cure plan (convergent first; every RUN §1 cure for T20 mapped to a named construction change)

### C1 — CONVERGENT 1 · Measured fit (reusability 68 + readability 68 both name it; the measured-fit leg OWNS this class — `recreation/guards/guard-measured-fit.md`: bounds are MEASURED post-fit from sampled glyph geometry, never formula-claimed)
Construction changes, all inside the sampler/fit path of `recreation.html`:
- **C1a — Post-fit glyph-bound measurement.** `sampleFacade` returns, per letter, its sampled ink bounds measured AFTER the final fitted font is fixed: distinct ink rows and ink columns per letter (from the alpha mask ∩ the letter's band), the owned grid-cell row/col extents, stem presence (≥1 ink column spanning ≥80% of the letter's ink height for stemmed glyphs) and counter preservation (letters with enclosed counters — O, A, D in the specimen lines — retain ≥1 enclosed unlit mask cell inside their ink bbox). The build record's "~29 px glyph" formula claim is deleted and replaced by these measured values converted at the 360 px stage (cell pitch 3.42 × 3.46 px × measured cell extents).
- **C1b — Coverage-based cell ownership.** Cell assignment moves from single centre-pixel sampling (which the readability return prices as erasing thin stems / closing counters) to area coverage: a cell is owned by a letter when mask coverage inside the cell's sample rect ≥ `CONFIG.sampleCoverageMin`. Ownership still derives wholly from runtime sampling of CONFIG text — no hand-placed cells (purity construction unchanged).
- **C1c — Two-axis fit with capacity diagnostic.** The auto-fit loop reduces the sample font until BOTH (i) widest line ink width ≤ `sampleW × sampleFitRatio` AND (ii) per-line ink height ≤ its line band height (`sampleH / lineCount`) hold — replacing the width-only fit with the 8 px floor. The floor itself becomes `CONFIG.sampleMinFontPx` (see C5). If either axis cannot fit at the floor, sampling returns a **capacity diagnostic** (named state field, e.g. `fitStatus: "over-capacity"` + the binding axis + the required vs available size) instead of silently overflowing; the diagnostic is asserted in the own-check suite and printed in the fit table.
- **C1d — Marquee measured fit.** The marquee string is measured (`measureText` at the candidate font) against its strip — hero width at stage = 136.8 px at 360 px — and the marquee font is fitted down from `marqueeFontPx` until measured ink width ≤ strip width, floor `marquee.fontMinPx`; below the floor the capacity diagnostic fires for the marquee element too. The fitted result (measured width, fitted font, margin) is a fit-table row.
- **C1e — Displayed-state verification at 360 px.** Partial (8 lit at 6499 / anchor 9 at 6500), anchor, and complete states are asserted with the measured bounds of C1a at the 360 px stage — not with cell-pitch proxies (A-C004-2).

### C5 — Remaining shaping literals into CONFIG + widened census (reusability 68)
Named literals move into CONFIG: sampler minimum font 8 → `sampleMinFontPx` (consumed by C1c) · orbit reference width 960 → `orbit.referenceWidthPx` (consumed by C6/render drift scaling, both neighbor and hero sites) · neon minimum stroke 1.5 → `geom.edgeMinStrokePx` · marquee font stack (`"bold … Arial, sans-serif"` literal in render) → `marquee.fontFamily` template consumed by the render font assignment · canvas minimum dimensions 300×170 → `stageMin.wPx / stageMin.hPx` consumed by `resize()`. ## 6 — Failure-point evaluation (priced for THIS item)

1. **Attribution (bundling).** Six cures land on two floor lenses that share causes; without the §4 staged checkpoints the wave could only print BUNDLED. Checkpoints isolate stage-level own-check effects, but lens attribution still prints BUNDLED unless a checkpoint isolates a lens-visible effect — the plan does not promise per-cure lens attribution.
2. **Cure interaction — fit shrink vs glyph legibility (the item's central tension).** C1c fits width AND line height by shrinking the sample font; a smaller font yields FEWER ink rows per letter, which is exactly readability's complaint (~6–7 rows). C1b coverage ownership + the capacity diagnostic are the counterweights, but if the specimen text at the specimen grid (40×48 over a 38%-width hero) cannot produce more measured ink rows, reusability rises while readability falls — net delta could miss +13. Priced in §7's stuck-lens hypothesis.
3. **Cure interaction — intensity dimming vs secondary legibility.** C2 dims the marquee and neighbor windows; dimmed too far, the marquee (already fitted smaller by C1d) drops toward illegibility and readability prices the hierarchy cure negatively. The luminance-ordering assertion bounds the ordering, not the absolute floor — the marquee's measured size floor (C1d) and its scale are asserted together in E2's stage check.
4. **Anchor leak / boundary flip (C4).** The re-derived anchor holds ONLY under inclusive-at-onset counting: an implementation reading `floor((t−start)/spacing)+1` vs a strict inequality flips the anchor state to 8 or 10 at exactly 6500. V3 asserts both sides of both boundaries (6499/6500, 10999/11000) precisely because the anchor and the completion now sit ON onsets.
5. **Evidence destruction.** The working file is the only attempt-1 source; §3's content copy + baseline + post-overwrite re-verification is the whole defence. The hardlink failure mode (A-C004-1's founding instance) and a create-once destination collision are both live risks in a 4-item fan-out sharing one run directory.
6. **Anchor leak into payloads.** Attempt-1 source comments carry amendment/cure references; comparison.html's prose carries checkpoint values and the anchor narrative. Neither may reach a payload: V8's allowlist excludes comparison.html entirely and neutralizes source comments before generation. A payload built from the un-neutralized source contaminates all five lenses at once.
7. **Instrument misread — harness measurement vs real raster.** The node harness's stub-canvas `measureText`/raster is a MODEL of the browser raster. If C1a's "measured" bounds are computed from the stub's idealized metrics, the readability/reusability lenses can price them as formula-claims again (guard-measured-fit §2's exact HIT). Mitigation priced into C1a: bounds derive from the post-fit alpha mask + cell-ownership pipeline the build actually runs, reported per letter; PIXEL-UNVERIFIED prints regardless; no filing upgrades harness measurement to rendered evidence.
8. **Fan-out contamination.** Four items build in parallel under one RUN.md, one fleet-wide `preservation-baseline.txt`, and shared seat files (HQ.json, heartbeat). This item writes ONLY its artifact directory + its attempt-tagged paths; shared-file writes are the seat's. Cross-item checkpoint or baseline edits would corrupt another item's evidence — priced as a stop-and-report, never a fix-in-place.
9. **Size split (§8).** C1 is the largest construction (sampler rework). If Execute grows toward a rebuild-from-scratch, the split rule binds: the attempt takes the CONVERGENT cures (C1, C2) + their interlocked stage (C3+C4) only, and C5/C6 defer IN WRITING under §8 — they are never silently dropped.
