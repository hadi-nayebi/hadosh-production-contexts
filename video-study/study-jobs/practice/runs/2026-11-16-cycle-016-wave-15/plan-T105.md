### C1 — CONVERGENT (motion 86, −14 · timing 86, trajectory item): rendered-weight skew

**Defect (both lenses, same arithmetic):** stacked complementary DOM opacities composite the outgoing scene at rendered weight (1−p)² (0.25 at midpoint) with the exposed stage contributing p(1−p); the visible fade accelerates beyond the measured proxy curve. DOM A+B = 1 was proved in attempt 1 and is not the priced quantity — rendered weight is.

**Construction change (named, primary route):** replace the stacked-opacity compositing with the **A-opaque-under / B-fades-over** construction (the alternative already on file from attempt 1's codex-plan-review, build-record §2 point 1, there set aside — this plan records that set-aside as superseded by the wave's convergent pricing):

- During dissolve and loop-fade return: `layerA.style.opacity = 1` (constant); `layerB.style.opacity = p` (dissolve) / `1 − q` (return, q = return progress). Because layer B's own field is opaque inside its layer, layer-opacity p composites B at rendered weight p and transmits A at rendered weight (1−p)·1 = 1−p. Rendered weights are therefore A = 1−p / B = p **by construction**, at every p — including p = 0.25 / 0.50 / 0.75 (rendered A = 0.75 / 0.50 / 0.25).
- Phase states: holdA → A rendered 1, B 0 (B opacity 0) · holdB → B opacity 1 (A beneath, fully occluded — occlusion asserted in the own-check suite, §Verify) · residual → B 0, A 1. The single `progressAt` resolver and phase boundaries D0–D3 are retained unchanged; only the opacity assignment in `render(t)` changes, plus `window.__state` gains distinct fields: `domOpacityA/domOpacityB` AND `renderedWeightA/renderedWeightB` (computed by the compositing model: renderedB = domOpacityB, renderedA = (1 − domOpacityB) × domOpacityA), so no future check can mistake DOM opacity for rendered weight again.
- **Deferred alternative (priced in §g):** the motion lens's isolated/additive compositing route (isolation + blend modes) is NOT the primary route — under PIXEL-UNVERIFIED its rendered result cannot be distinguished from a model assertion in this seat, and blend-mode behaviour varies by engine; the A-opaque route's rendered weights follow from plain source-over compositing arithmetic that the source-bound model can assert exactly. If the re-score wave prices the A-opaque route as still skewed, the additive route is the named next-attempt fallback (WHY scaffold, §f).

**Cure interaction priced here:** at midpoint the incoming wordmark now sits over an A scene rendered at 0.50 instead of 0.25 — A is *more* visible at midpoint than in attempt 1. Readability's attempt-1 note credited the skew with helping the incoming subject ("supports the incoming subject's readability over the ghosted webpage"). C3's label separation (below) is the compensating construction, and the Verify checklist asserts midpoint label separation explicitly so this interaction is measured, not hoped away.
