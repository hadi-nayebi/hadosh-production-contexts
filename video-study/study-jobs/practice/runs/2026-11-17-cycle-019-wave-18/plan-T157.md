### Owner cures (outrank all other cures)

**K1 — Galaxy arms + core capped at the CONFIG reserve (Owner Cure 1).** *(readability)*
- `codex/lens-readability.md` finding 2: "Galaxy construction assigns both arms and core opacity `reserveIntensity + galaxyOpacityBoost`: 0.45 + 0.25 = **0.70**, above the lens's ≤0.5 requirement… **Cure:** cap galaxy arms and core at 0.5, preferably the configured 0.45 reserve." scores.md concurs: "remove or negate galaxyOpacityBoost so the scope never exceeds 0.5."
- **Construction change (full-strength ceiling, enforced at both sites):** DELETE `palette.galaxyOpacityBoost` from CONFIG. Both opacity sites (galaxy polyline + core circle) take their opacity from ONE bounded helper/value — effective galaxy opacity = `Math.min(cfg.specks.reserveIntensity, 0.5)` (with a lower bound of 0) — never `cfg.specks.reserveIntensity` raw and never any additive boost. The default reserve stays 0.45, so the default renders exactly 0.45. A swapped reserve above 0.5 is **safely bounded to 0.5 before rendering** at both sites; it is never rendered above 0.5. Deleting the boost key (not zeroing it) is deliberate: a zeroed boost key invites re-adding a positive value under the same name; the census then proves the surface is gone.
- **Own-check (three cases, all asserted at S1 — the first cure checkpoint — and re-run in §7 V1/V2):** (a) default reserve 0.45 → computed arm opacity == 0.45 AND core opacity == 0.45; (b) lower reserve, e.g. 0.3 → arms AND core render 0.3; (c) above-ceiling reserve, e.g. 0.9 → arms AND core render 0.5 exactly (bounded), never 0.9. Any site rendering above 0.5 in any case fails the check and blocks the next stage.

**K3 — Region draws on: progressive perimeter reveal.** *(motion + timing)*
- `codex/lens-motion.md` finding 1: "region initialization sets `stroke-dasharray="9 7"`; `frame()` changes its dash offset and switches opacity to 1 immediately when `regionP > 0`. This reveals the whole dashed ellipse at once, then moves its dashes around the perimeter… **Cure:** reveal the dashed ellipse through a separate continuous stroke mask whose dash offset exposes progressively more perimeter during 4500–6500 ms."
- `codex/lens-timing.md`: "changing `stroke-dashoffset` shifts those dashes around an already complete ellipse… the nominal two-second draw becomes moving dashes… **Cure:** reveal the dashed ellipse progressively with a separate mask or equivalent path-length reveal over 4500–6500 ms, preserving badge onset at 6800 ms. Verify visible perimeter coverage at start, midpoint, and completion; `regionP` alone does not establish it."
- **Construction change — mask specified explicitly (units, bounds, reveal stroke, background):** keep the dashed ellipse (`regionEl`, dashSeg 9 / dashGap 7 from CONFIG) as the visible stroke; add an SVG `<mask>` with: `maskUnits="userSpaceOnUse"` (design px, the stage's coordinate system); bounds `x = region.cx − region.rx − region.maskW`, `y = region.cy − region.ry − region.maskW`, `width = 2 × (region.rx + region.maskW)`, `height = 2 × (region.ry + region.maskW)` (covers the full stroked ellipse with margin); background treatment — a rect filling exactly those bounds with `fill="#000"` (black = fully masking) drawn FIRST inside the mask; reveal stroke — a second ellipse (same CONFIG cx/cy/rx/ry) drawn after the rect with `fill="none"`, `stroke="#fff"` (white = fully revealing), CONTINUOUS stroke, stroke-width = new CONFIG key `region.maskW` (≥ region.dashW, defaulting wider than dashW, e.g. dashW + 2 — final value is the builder's, recorded in the build record), `stroke-dasharray = regionCirc(cfg)`, `stroke-dashoffset = (1 − regionP) × regionCirc(cfg)`. The mask is attached to the visible ellipse by `regionEl.setAttribute("mask", "url(#<maskId>)")` where `<maskId>` is the generated mask element's own id. The old behaviour (opacity flip at regionP > 0 + dashoffset marching on the dashed stroke itself) is removed: the dashed ellipse's own dashoffset stays 0. Allocation unchanged: drawStartMs 4500, drawMs 2000, badge onset 6800 untouched (A-C012-2: no shared mapping changes, so no dependent re-derivation is owed — regionP's definition does not change, only its displayed consequence).
- **`regionVisibleFrac` — definition corrected (never defined as equal to regionP):** `stateAt()` exposes `regionVisibleFrac` as a NEW state field distinct from regionP, computed as `(regionCirc(cfg) − <mask reveal ellipse's actual applied stroke-dashoffset, read back from the generated mask element>) / regionCirc(cfg)`. It is a GEOMETRIC coverage figure derived from the mask element as built, not an alias for regionP. Actual rendered coverage is labelled **PIXEL-UNVERIFIED** everywhere it is claimed (§3 D4, §6 FP-9, build record): no source or geometric check in this plan establishes rendered pixels.
- **Independent mask verification (S3 checkpoint, §5/§6/§7):** the own-check parses the generated DOM independently of the offset arithmetic and asserts ALL of: the mask element exists with the specified maskUnits and bounds; its first child is the black background rect filling those bounds; its reveal ellipse carries white (`#fff`) stroke, `fill="none"`, stroke-width == cfg.region.maskW, dasharray == regionCirc(cfg); and `regionEl`'s `mask` attribute references that mask element's id (attachment). **The S3 checkpoint FAILS on an invalid or disconnected mask — missing element, wrong units/bounds, missing black rect, non-white reveal stroke, or a mask attribute that does not resolve to that element — despite correct dash offsets.** Correct offsets alone never pass S3.
