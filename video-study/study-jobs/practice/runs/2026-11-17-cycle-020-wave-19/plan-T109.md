### C2 — CONVERGENT (motion 81 + timing 82): stagger normalized inside morphMs + return retraces the exact forward trajectory
- **Findings.** Motion return: "At morph end, 7000 ms, cardMid is only 98.4% collapsed and cardLow 93.9%. They continue changing until 7120 and 7240 ms, violating the requirement that settle affect triangles alone"; and "Both lower cards return using the same unstaggered progress. Their forward trajectories differ, so this does not retrace the forward transformation." Timing return: "The stagger also extends lower-card collapse 120/240 ms into the nominal settle phase; the phase label therefore understates continuing transition activity."
- **Construction change — ONE piecewise trajectory per collapsing element, covering preparation + morph (this formula supersedes any morph-only formula elsewhere in this plan).** Let `P0 = C1 − stepMs` (preparation onset), `P1 = C1` (morph onset), `P2 = C2 = C1 + morphMs` (morph end). For element *e* with CONFIG `stagger` *sₑ* and CONFIG prep fraction *fₑ* (`morph.prepFraction`, 0 < *fₑ* < 1 — the fraction of its collapse completed by P1), the single trajectory *Qₑ(t)* is:
  - *t* < P0: *Qₑ* = 0.
  - **Preparation piece**, P0 ≤ *t* < P1: *Qₑ(t)* = *fₑ* · `clamp01((t − P0 − sₑ·fₑ) / (stepMs − sₑ·fₑ))` — stagger applies inside preparation too, scaled by *fₑ* (the same stagger, proportionally), so the element's effective start is delayed by *sₑ·fₑ*, never unstaggered.
  - **Morph piece**, P1 ≤ *t* ≤ P2: *Qₑ(t)* = *fₑ* + (1 − *fₑ*) · `clamp01((t − P1 − sₑ·(1 − fₑ)) / (morphMs − sₑ·(1 − fₑ)))` — the remaining (1 − *fₑ*) of the collapse runs on the remaining (1 − *fₑ*)-scaled stagger, so stagger is applied **consistently across the whole trajectory** (total effective delay *sₑ·fₑ* + *sₑ·(1 − fₑ)* = *sₑ*, partitioned by the prep fraction, not dropped or double-counted).
  - *t* ≥ P2: *Qₑ* = 1. Validation rejects any configuration with *sₑ·fₑ* ≥ stepMs or *sₑ·(1 − fₑ)* ≥ morphMs (a denominator ≤ 0 is a named validation problem under C7).
  - **Continuity, asserted not assumed:** at P0, *Qₑ* = 0 from both sides (the preparation piece is 0 until its delayed start); at P1, the preparation piece reaches exactly *fₑ* (its clamp saturates at P1 by construction) and the morph piece starts at exactly *fₑ* — the suite asserts |*Qₑ*(P1⁻) − *Qₑ*(P1⁺)| = 0 and |*Qₑ*(P0⁻) − *Qₑ*(P0⁺)| = 0 for every collapsing element, and that no element's state restarts, jumps, or re-begins at morph onset. At `t = C2` every staggered element is at exactly its terminal state (*Qₑ* = 1), and the settle window `[C2, C3)` moves triangles alone (asserted at sample points across settle for every non-triangle element).
  - **Return mirrors the ENTIRE trajectory, preparation included.** The return phase evaluates the same *Qₑ* at the mirrored time over the full span [P0, P2] — return state at mirrored progress *p* is *Qₑ*(P0 + (1 − *p*)·(P2 − P0)) — instead of the current single global `1 − easeFn(...)` applied to searchBar/cardMid/cardLow, and instead of any morph-only mirror. Forward and reverse share one trajectory definition per behaviour (built inside C1's dispatch), so retracing is true by construction. The suite asserts, per collapsing element, sampled forward states at time *t* equal sampled return states at the mirrored time **across the preparation portion too** (sampled *t* inside [P0, P1) explicitly included, not only inside the morph), plus terminal completion at P2 and reverse equality at both joins (the mirrored return passes through *Qₑ* = *fₑ* at the mirrored P1 and *Qₑ* = 0 at the mirrored P0).

### C4 — Motion 81 (single-lens): "collapse-down" centres genuinely sink
- **Finding.** Motion return: "Because height shrinks while the top moves only 10 px downward, cardMid's centre rises 8 px and cardLow's rises 5 px."
- **Construction change.** Centre-derived sink: the collapse computes the element's **centre** trajectory first — `centre(q) = y + sinkPx · q` — and derives `top = centre(q) − h·(1−q)/2` from it, instead of fixing top and letting the centre fall out of the height shrink. `morph.sinkPx` thereby changes semantics from top-offset to centre travel (the CONFIG comment, if any, and the build record must say so plainly). Suite asserts, per collapsing element at sampled q: centre is monotonically non-decreasing (never rises) and centre(1) − centre(0) = sinkPx exactly.

The filing therefore distinguishes two evidence classes, printed separately and never conflated: (1) **cure-specific own-check evidence** — the stage suites' construction assertions (mapping-change swap leg, terminal-at-C2, disjointness rows, …), which may be credited cure-by-cure or stage-by-stage because they measure construction effects directly; and (2) the **BUNDLED final lens delta** — every lens's signed Δ is the whole attempt's movement, printed **BUNDLED** in the filing, with no per-cure or per-stage split.
