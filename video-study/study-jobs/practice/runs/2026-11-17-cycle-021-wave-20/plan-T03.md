### C2 — `maxVisibleLines` must cap the visible window INCLUDING future lines' slots (reusability 68, head cause 2; convergent with motion 92's only deduction, −8: future prompt glyphs visible from initialization)
- **Construction:** the visible set becomes a true active-anchored window. A line `li` is displayed iff `trimStart ≤ li ≤ active` (before line 1 starts, only line 0's slot stands, empty). Future lines (`li > active`) are `display:none` from t=0 — no prompt, no reserved height on stage. Window slides **only at line boundaries**, as before.
- **Prompt activation (motion cure, same construction):** a line's prompt span carries `visibility:hidden` until `li ≤ active`; its width is retained in layout, so activation never shifts the line.
- **Reservation — the ONE final measurement (unified with C4, Codex plan review finding 4):** future lines are `display:none` in the live stage and therefore supply **nothing** — no height, no reservation, no anchor. The reservation comes from a single build-time measurement pass, shared by C2 and C4: before the live stage's display states are applied, every line is laid out in an off-screen measurement stage (displayed, `visibility:hidden`, positioned off-screen, with the live stage's exact width, font size, line-height and padding — no `display:none` anywhere in it), each line's full-layout height is recorded, and `maxWindowHeight` = max over all sliding windows of Σ per-line heights. The live stage then gets `min-height = maxWindowHeight` (and `position:relative` for C4's cursor). This probe pass is the only measurement construction in the attempt: C4's slot heights ARE these per-line probe heights (asserted equal to the displayed line's height when that line is live), and there is no second, intrinsic-height mechanism.
- **Anchoring:** displayed lines stack from the stage top; a displayed line's model top = Σ probe heights of the displayed lines above it. Completed lines therefore do not move when a slot enters/leaves at a boundary except by the boundary slide itself — the contract's named, lawful shift, of exactly the departed/entered slot's probe height.
- **Invalidation (font/resize):** the measurement is invalidated and re-run — clamp font size recomputed FIRST, then the probe pass re-run, `min-height` reset, then re-render — on (i) window resize, and (ii) `document.fonts.ready` resolution (late font arrival changes every height). A stale measurement is never reused after either event; the resize handler is this one unified handler for C2 + C4 (C4's resize-font cure lands here, not as a second handler).
- **Own-check (effect mapping):** elapsed sweep on a 6-line config, maxVisibleLines=3 — at every sampled elapsed: displayed count ≤3, no `li > active` displayed, prompt visibility ⇔ `li ≤ active`; specimen default (3 lines, max 3): displayed progression exactly 1→2→3 at line starts. Adversarial: maxVisibleLines=1; maxVisibleLines ≥ line count; override `?maxVisibleLines=0/abc` ⇒ clamped ≥1 / ignored. **Glyph positions across line boundaries (finding 4):** for every boundary slide in the sweep, each surviving displayed line's model top changes by exactly the departed/entered slot's probe height and by no other amount, and every surviving glyph's intra-line row assignment is unchanged; the probe-pass heights are asserted to be the heights the reservation uses (one measurement, not two). Rendered pixel coordinates remain **PIXEL-UNVERIFIED** (A-C002-2) — these are layout-model assertions, never claimed as measured pixels.

### C4 — Readability: word-wrap reflow during reveal (readability 78, head cause; cursor-space approximation priced in the same return)
- **Construction (the return's own prescription):** lay the complete text out **once** and reveal without removing layout participation. Each line's text is built at build time as one span per grapheme cluster, all present in the DOM from frame 0; per-frame updates toggle only span `visibility` (shown ⇔ index < stateAt count). Word wrap is computed on the full text at t=0, so a partially revealed word can never jump rows; revealed characters occupy stable positions **intra-line**, not merely in reserved height.
- **Cursor at the revealed grapheme boundary — construction amended (Codex plan review finding 3):** the earlier trailing-spacer design is **withdrawn**: a cursor parked at a permanent trailing spacer follows the whole line including its invisible text, so during partial typing it does NOT mark the insertion point — the property the prior readability return credits the cursor for. There is no trailing spacer. Instead: the single cursor element is `position:absolute` inside its line (the line is `position:relative`), i.e. **out of flow — it adds zero width and zero height and cannot affect wrapping by construction**. Per frame, its `left`/`top` are set from the measured boundary: the boundary is the last revealed grapheme span; cursor `left` = that span's right edge relative to the line box, `top` = that span's top (both from `getBoundingClientRect()` of span and line at runtime). Boundary definitions for every state: **beginning** (0 revealed) → left = the prompt span's right edge, top = first row's top; **partial-word** → immediately after the last revealed cluster, before the unrevealed remainder of the same word; **wrapped-row** → the boundary span sits on a continuation row, so `top` is that row's top and the cursor appears on the correct row, not the line's first row; **completed** → after the final cluster, at the line's end, where it holds until the next line activates.
- **Reservation:** C4 no longer claims an intrinsic-height mechanism. Slot heights and the stage reservation are the ONE unified probe measurement defined in C2 (finding 4): future lines are `display:none` in the live stage and supply nothing; the off-screen measurement pass supplies every height this cure relies on. The old live probe element is removed from the render path; the measurement pass is a build/invalidation-time construction, not a rendered line.
- **Invariants preserved:** exactly 1 cursor element created once, never rebuilt; 0 `innerHTML` writes; per-frame path touches span visibility classes + the cursor's `left`/`top` only (the attempt-2 "text nodes only" census is superseded by this named equivalent and the build record must print the new census terms). Grapheme integrity: span concatenation = full line text at every elapsed; no intermediate state splits a cluster.
- **Resize/font:** the unified C2 invalidation handler governs (clamp font recomputed first — attempt-2 remeasured reservations without recalculating font, readability return — then the probe pass re-runs, then re-render, which re-derives the cursor boundary under the new metrics).
- **Own-check (effect mapping):** elapsed→visible-span count equals `stateAt` counts for specimen + swap configs (index→effect, A-C002-1); span order/concatenation identity at all sampled elapsed; source census (1 cursor creation, 0 innerHTML, span count = total clusters). **Cursor-boundary states (finding 3):** the boundary model is asserted in all four states — beginning (cursor model position = prompt right edge, first row), partial-word (position = right edge of the last revealed cluster mid-word, with the word's unrevealed remainder following it on the same row), wrapped-row (the boundary cluster falls on a continuation row ⇒ cursor model top = that row's top), completed (position = right edge of the final cluster) — and the **wrapping invariant**: every span's row assignment is identical at every sampled elapsed and identical with the cursor shown, hidden, or removed (out-of-flow construction ⇒ no cursor state may re-wrap text). **Coordinates remain PIXEL-UNVERIFIED** (no working render route in this seat, A-C002-2): the runtime construction measures real rects in a browser, but this seat's checks assert the boundary MODEL and the source construction, never measured pixels — priced as a residual risk in §5, never claimed as a pass.
