# Codex review — codex-plan-review (practice)

_Repeated Codex review type, defined in this job's own guards layer (phase-guard augmentation, 2026-11-14). The recurring plan risk in practice is specific: a re-attempt plan that looks complete because it lists cures, while the rebuild it proposes cannot attribute a score movement to any one of them, quietly drops a cure, or leaves the non-beating branch — half of this job's lawful outcomes (OBJECTIVE) — unplanned until close._

## Standing header (every firing carries it)
1. Consumer: practice INSTRUCTION §2 (Plan) — the attack lands before `jev-plan-exit.md` is called; the plan's author (the cycle's per-item agent task) consumes the return by amending the plan or by printing why a finding does not apply.
2. Decision priced: whether this item's cure plan may go to the plan-exit gate as written, or must be revised first — and specifically whether its failure-point evaluation is real (this item, this construction) or generic.
3. Working record: the cycle's RUN.md Plan section for the item.
4. Body-write: the return files verbatim in the cycle's run directory (`runs/<date>-cycle-<NNN>-wave-<K>/codex-plan-review-<item>-return.md`); every accepted finding amends the plan text in RUN.md in the same cycle, and rejected findings carry their printed reason beside the return pointer. A return naming no body-write is incomplete.

## The review (instruction to Codex)
Attack this practice re-attempt plan. The plan's job is to beat a filed score with named cures, or to file a WHY that names a real plateau — attack it as a plan that could do neither honestly.
- ATTRIBUTION ATTACK: where one construction change carries several cures (founding instance: T15 attempt 2's flow-field rebuild carrying OWNER CURE 1 + OWNER CURE 2 + priced cure 1), can a later lens movement be attributed? If not, what instrumentation or staging (e.g. per-cure own-checks before the wave) would make it attributable, and does the plan carry it?
- INTERACTION ATTACK: price cure interactions the plan does not name (construction changes that fight each other — e.g. fitting/wrap changes vs tempo proportions; intensity separation vs dust density/motion feel; reserve fraction vs fitting targets on dense phrases).
- EVIDENCE-DESTRUCTION ATTACK: walk the Execute checklist in order — is there any step order in which a prior attempt file, the comparison's ORIGINAL side, or a filed return can be overwritten, re-pointed early, or re-averaged? Prior attempts are evidence (§6.1); a plan that can destroy them fails here regardless of its cures.
- ANCHOR ATTACK: find any path by which prior scores reach a lens run as anchors (fed artifacts, build record wording, scores.md excerpts in a lens payload). The delta is the seat's arithmetic after the wave, never a lens's negotiation.
- UNPLANNED-BRANCH ATTACK: assume the attempt does NOT beat its prior average. Walk the plan: is the WHY filing fully scaffolded (cure-by-cure slots, stuck-lens hypothesis, jev-plateau evidence needs), or would close improvise it? Also assume the attempt PASSES: is the tier hand-off to style-library actually a step, with the scores.md pointer it needs?
- SPLIT ATTACK: if the plan is effectively a rebuild-from-scratch, does it obey §8 (convergent cures in this attempt, the rest deferred in writing with reasons), or does it take the whole rebuild whole and call the size rule satisfied?
Close with exactly one verdict line: `PLAN: SURVIVES` or `PLAN: REVISE BEFORE GATE` followed by the numbered findings, each tagged with the checklist/section it amends.
