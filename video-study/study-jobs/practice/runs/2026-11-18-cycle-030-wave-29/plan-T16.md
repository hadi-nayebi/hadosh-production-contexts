## 1) Cure plan

### HEAD CURE — R1 strict-readable gating construction · Stage 1 · primary lens: timing · THE PLATEAU CLASS (A-C029-2 disposition)

This is the class's construction-family change, exactly as the seat verdict at the attempt-9 filing specifies. **A counter correction instead of this gating construction is a deviation** (another draw-binding patch, another presented-count fix, or a dwell-only re-tune does not satisfy this cure and prints as a deviation in the run record).

**The a9 defect, in source terms (verified firsthand this Plan):** `draw()` computes the strict predicate for the current page's assigned front set (`strict` = every assigned particle `isReadable(p, simT)` — settled ∧ turn complete (`now − turnT0 ≥ turnEffCur`) ∧ registration complete) and records presented-readable counts/dwell from it — but the DOM counter write sits **below and outside** that branch: `const cv = curPage + "/" + CONFIG.pageCount; if (counterNum.textContent !== cv) { … }` executes on every flip draw. The numeral therefore names a page that may still be turning or registering.

**Construction (all four parts are the cure; no part is optional):**
1. **Qualified presented state.** A new run-state value — the *presented page* (`presentedPage`, 0 = none qualified yet) — distinct from `curPage` (the simulation's current page) and from the presented-readable counters. It changes **only** inside `draw()`'s strict branch: at a draw where the strict predicate holds for the page the numeral would name (`curPage`, complete assigned front set present, `assigned === required`, `assigned > 0`), `presentedPage` is set to that page. No other code path writes it (see the A-C012-2 sweep below — `step()`'s three dispatch sites and `resetRun()` are the named risks).
2. **The DOM numeral renders the qualified value only — qualification is PER CYCLE (amended Cycle-030 plan review, Finding 2).** The counter text is written from `presentedPage`, never from `curPage`: on a strict-readable draw of page N the numeral becomes `N/pageCount`; on every other draw it **holds the previous qualified value unchanged within the same cycle**. `presentedPage` is cycle-scoped: at every loop seam (flip restart / new cycle entry) it resets to 0 (none qualified in this cycle) **and the counter returns to its un-presented state (opacity 0, no visible numeral)** until the new cycle's page 1 earns its first strict draw — a second loop must never reveal the prior cycle's `14/14` (or any prior-cycle value) before the new page 1 qualifies. The same reset applies on `resetRun()` and after a refused `revalidate()` (which changes neither the live cycle's qualified value nor its visibility — see the M1 sweep). Before any page has qualified in the current cycle (notably page 1 at load — its registration completes ≈98 ms in, per the a9 timing return), the counter stays in its un-presented state (hidden, as `step()`'s flip entry already sets counter opacity with text "written by draw() only") — it never shows an unqualified `1/14`. `diagnostics.counterPresentedValues` records only qualified writes, in order, tagged by cycle index, so a cross-cycle leak is mechanically visible in the record.
3. **Strict dwell provided at supported callback cadences — ENFORCEABLE FORM (amended Cycle-030 plan review, Finding 1).** Gating alone would strand the rapid pages: at defaults the strict window is **20 ms** (87.5 ms interval − 67.5 ms effective turn), which contained a strict draw in **0/32** presented cells at 50 ms steps on the a9 draw-timestamp instrument (opportunities 8/32; 60 fps 32/32). The construction therefore reserves a strict-dwell floor inside every page interval: a new validated CONFIG key **`strictDwellMs` (default 50)** — one full step of the coarsest supported cadence (50 ms steps; the finer supported cadence is 60 fps ≈16.7 ms) — and the effective turn is capped against it: `turnEffForInterval` returns `min(turnMs, intervalMs − strictDwellMs)` for intervals that can carry it. At defaults the rapid turn becomes 37.5 ms and the strict window 50 ms, which guarantees ≥1 draw inside the window on **any** 50 ms grid regardless of phase offset, and ≥2 at 60 fps. The preserved anchors do not move (checkpoints 1@0 · 6@1500 · 14@2200; flipMs 2600; the interval ladder 300 → 87.5 ms is schedule-derived and untouched — the dwell is bought from the turn, not from the anchors). **Effective strict start — defined, not assumed:** for each page, `strictStart = max(turnCompletionTime, lastRequiredParticleRegistrationTime)`, both read on the actual `frame()` callback clock (simulation time at the callback that first observes the condition), and the effective strict window is `intervalEnd − strictStart`. The turn alone never defines the window: at the rapid default the 37.5 ms turn + 50 ms reserve consumes exactly the 87.5 ms interval, while the travel+stagger floor is 36.4 ms and the scheduler clamps registration to ≥1 ms, so if registration binds, the effective window is **shorter** than 50 ms and the nominal claim fails — the window is therefore always the **measured** `strictStart`-derived window, never `intervalMs − turnEff`. **Supported-cadence requirement (the stage's pass condition, stated once):** every rapid page (6–13) must achieve **≥1 strict draw at 50 ms steps at every tested offset AND ≥2 strict draws at 60 fps (≈16.7 ms steps) at every tested offset** — one draw is the qualification floor at the coarse cadence; two draws is the requirement at 60 fps (a 50 ms window on a 16.7 ms grid contains ≥2 callbacks at any phase, so a single 60 fps draw proves the window is materially under 50 ms). **STOP RULE (resolves the former step-7/step-9 conflict in favour of the stop):** if the Stage-1 measurement ladder shows the supported-cadence requirement cannot be met with the preserved anchors — i.e. no reserve/turn combination yields the required draws at both cadences — **Stage 1 STOPS: no smaller reserve is bound as a pass, no shortfall is carried to Verify as a mere risk, and no later stage opens.** The stop, the measured ladder, and the binding term (turn vs registration) file in the Stage-1 own-check and the run record as a head-cure failure routed per §5g (Finding 6). Binding a measured reserve smaller than the requirement and proceeding is a deviation. **A-C011-4 feasibility ladder (Execute step 7):** Execute measures the actual `strictStart` offset + effective window on the Stage-1 source (ladder: turnEff ∈ {67.5, 50, 37.5} → measured `strictStart` + window + draws at both cadences) and binds only a reserve the measurement proves meets the requirement above; an unmeasured 50 ms claim does not ship. Intervals too short to carry travel + the reserve are refused by the gate (the a7 binding construction), never run past.
4. **One reserve, one key (A-C012-2 hygiene).** `strictDwellMs` supersedes `minSettledHoldMs` in both of that key's consuming roles (the turn cap in `turnEffForInterval`, the budget need in `computeSchedule()`/`assessFeasibility()`); `minSettledHoldMs` is retired into the frozen schema in the same stage, so no second reserve key survives to diverge. If the Stage-1 census finds a third consumer of `minSettledHoldMs`, it is re-derived in the same stage or the retirement does not happen and the divergence prints.

**What this cure is expected to move:** the timing −6 fast-turn class and readability's counter class are the priced recovery; motion's counter share is noted, not primary. The D1 ≥80 ms criterion is **not** claimed (see §2 deferral D1): a 50 ms strict window inside an 87.5 ms interval is the maximum the preserved anchors + travel floor leave after a non-degenerate turn, and the filing must say so.
