## 1. What it judges
- Surface judged: the cycle RUN.md's Plan (§2 product): signal set + comment-sampling rule + separation/write plan + the Execute checklist and Verify checklist the Plan must produce.
- Call point: reception-analysis INSTRUCTION §2, at the gate out. The phase advances on the verdict's recorded disposition (applied, or set aside with reason). An unfired call makes the cycle INCOMPLETE.
- What it gates: the right to capture and read audience data under this plan.

## 2. Instruction (the model's charge)
Judge whether this plan, executed exactly as written, can only produce an earned reception.md. Price, in order: (1) CRAFT-LEAK-BY-DESIGN — the founding risk: does any planned signal, theme-coding rule, or pre-drafted headline price the work's CRAFT from engagement data, or engagement from craft impressions? Standing leak forms for this job: a comment-theme category that is a craft verdict in costume ("viewers loved the editing") without a comment-evidence rule behind it · a spread headline drafted before capture · a retention inference planned to be stated as fact. (2) SIGNAL TRACEABILITY — every signal in the set traces to a data class the Observe inventory evidenced as EXISTING for this specimen; a signal planned against an absence (e.g. a retention curve for an Instagram reel) fails here, not in Verify. (3) SAMPLING-RULE PRECEDENCE — the comment-sampling rule is fully stated in the Plan, before any comment is read, sized to the comment count the inventory found, and cannot be re-chosen after themes are seen. (4) BASELINE REALITY — any planned delta or spread figure names its base (follower/subscriber count at capture, or the prior capture) and that base is in the inventory; a spread claim with no base in hand is unpriceable and must be cut or cured in Plan. (5) CHECKLIST PRODUCTS — the Plan's named products exist: an Execute checklist (capture order, spread arithmetic, theme extraction form) and a Verify checklist naming an INSTRUMENT per property (the §5 audits + the craft-quarantine grep + jev-reception), not intentions. (6) FAILURE POINTS + REDUCTIONS — the plan evaluates its own failure points (single capture → no velocity · comment access partial → sample bias · §8 hand-off path to video-digestion wrong) and names anything it quietly dropped from the objective (a signal class abandoned, a specimen scope narrowed) as a reduction, in the open. Score 0–1 per dimension and classify defects.

## 4. Output space
- Verdict classes: **EXECUTE · REVISE · RETURN-TO-OBSERVE**.
- Dimensions (0–1): separation-plan integrity · signal traceability · sampling-rule precedence · baseline reality · checklist completeness · failure-point pricing.
- Rejection taxonomy (one primary): CRAFT-LEAK-BY-DESIGN · SIGNAL-BEYOND-DATA · SAMPLING-RULE-LATE (rule absent, vague, or post-hoc) · BASELINE-MISSING · CHECKLIST-HOLLOW (Verify items name intentions, no instrument) · REDUCTION-UNNAMED (objective scope dropped silently).
- Accepted profiles travel: the profile is cited at the head of RUN.md's Execute section; REVISE items must be cured and the revised Plan re-judged before Execute opens.

## 5. Floors and disposition
- separation-plan integrity < 1.0 with the leak as the plan's headline signal → RETURN-TO-OBSERVE; a local, removable leak → REVISE with the leaking element struck.
- Sampling rule absent or post-hoc → REVISE minimum; Execute is blocked until a compliant rule stands and is re-judged.
- signal traceability < 0.5 or any dimension < 0.4 → RETURN-TO-OBSERVE.
- Disposition: the verdict is advisory — reviewed by the runner, applied or set aside with the miss recorded in Condense. The verdict + disposition land in the cycle RUN + verdict-history.md either way.
