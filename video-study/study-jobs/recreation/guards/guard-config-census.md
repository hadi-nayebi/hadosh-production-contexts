# guard-config-census — the config-census leg, v3.1 codified (recreation + practice)

_Built 2026-11-15 on HQ's charge (owed checks, 2026-11-15 ~08:02 EST), codifying candidate v3.1 from recreation Cycle-008 Wave-6's Condense (which extended Wave-5's v3, which extended v2). Before this build the census existed only as candidacy text inside RUN records and as builder-run greps whose blind spots the scoring lenses kept finding. This file is the leg's standing definition. It owns ONE defect class: reusability failures whose mechanism is **config incompleteness** — shaping decisions living outside CONFIG, or CONFIG keys that promise control they do not exert (reusability stuck across Waves 3–6 and binding in practice waves since). It does NOT own timing, fit (guard-measured-fit's class), or content failures._

## What the leg checks (per item, on the final recreation.html)
1. **All-literal scan.** Every literal outside the CONFIG block is counted and classified: hex/rgba colors · durations · geometry values · numeric constants and formula coefficients. Each constant is classified in print as **subject-shaping** (it shapes what the subject looks like or how it moves → must be a CONFIG key; standing outside = HIT) or **structural** (loop bounds, indices, mathematical identities → exempt, classification printed per constant; the sr/3, sr/6 misclassification of Wave 6 is the cautionary instance — ratios that scale the subject are subject-shaping). **Addendum landed 2026-11-16 (recreation Cycle 024 Condense — the A9.6 background-coefficient clause, discharging Cycle 023's named consumer):** coefficients that set a BACKGROUND layer's growth, opacity, size, or intensity AGAINST the subject (dust-cloud growth/opacity, plate glow, reserve-field density/intensity, backdrop scale) are **subject-shaping** whenever a scoring lens can price them against the subject — a background layer's coefficients are subject-shaping when the readability or reusability lens can price them, and they must be CONFIG keys or be classified HIT; classifying them "structural" because they sit in a background generator is the named miss. Forcing evidence: T140 (Cycle 023) — the builder's census classified the dust coefficients structural while the reusability lens priced them subject-shaping at 78, the item's minimum (filed return: `hidden_files/study/recreations/T140-repetition-chant/codex/lens-reusability.md`, SCORE: 78, seat-verified at Cycle 024's Condense); INSTRUCTION Amendment A9.6 resolved the classification in the instruction layer the same cycle, and this addendum lands the same rule in the guard's own classification text. **Clarification landed 2026-11-15 (recreation Cycle 013 Condense, on T75's reusability-lens miss):** constants inside scene/asset GENERATORS that scale or shape the generated subject (skyline/scene geometry, generator seeds' geometric coefficients) are subject-shaping, not structural, whenever changing them changes what the subject looks like; font-family stacks named in CSS are likewise subject-shaping (typography is a shaping decision) and must be CONFIG keys or be classified HIT — a census that passes either class as "structural" has missed its own class. **Addendum landed 2026-11-16 (recreation Cycle 021 Condense, under codex-condense REVISE — invariant-exemption bar):** the declared-invariant classification is barred for any literal that implements a dimension a CONFIG key promises — if a geom.* key names it, the literals constructing it are subject-shaping and must read from the key. Forcing evidence: T130 (Cycle 021) — the car silhouette path coordinates and wheel offsets were exempted as declared invariants while geom.carW/carH promised that control; reusability lens 68.
2. **Application-site resolution.** Every CONFIG key is resolved to at least one application site in the code, **including nested and array-member keys** (`artworkTags[].level` class — Wave 6, T43). A key with no application site is a HIT (unapplied key = promised control that does not exist). **Addendum landed 2026-11-16 (recreation Cycle 021 Condense, under codex-condense REVISE — value-flow site validity):** an application site counts only where the key's value flows into the construction of the subject the key names (e.g. carW/carH → the car body's path/transform and wheel geometry). A key whose only occurrences are its declaration, storage, or a consumer other than its named subject (e.g. carW read only by a puff-midpoint computation) is UNAPPLIED = HIT. Forcing evidence: T130 (Cycle 021) — census HITs 0 with "geom.carW/carH → car scale declaration" while carH occurred only in its declaration and the car path/wheels were hardcoded; reusability lens 68.
3. **CSS-variable setter check.** A CONFIG key consumed through a CSS variable whose setter never assigns it is a HIT (the `geom.pieSize` false-negative class, Wave 6 T38: a reference, not a literal — invisible to literal greps, owned here explicitly).

## Output form (filed per item, pre-wave)
`config-census.md` in the item's artifact directory: literal count by class with the per-constant classification, the key→site resolution table, the CSS-variable check, and a HIT list (empty = PASS for this leg). The wave's RUN cites the path + hit count per item. The leg's verdict is ADVISORY (owner's 2026-11-14 ruling): hits are cured before scoring where the builder can, or carried into the wave printed with their disposition. The FIRING is not advisory: a wave whose record lacks the census for any item prints INCOMPLETE.

## Call point
Pre-wave, per item, after the build and BEFORE the five-lens scoring wave (wired into recreation INSTRUCTION Amendment A6 and practice INSTRUCTION Amendment A-C008). Practice re-attempts fire the same leg on the new attempt's file; the census runs against the attempt's own CONFIG, never the prior attempt's.

## Scope honesty
This leg proves the recreation is re-drivable from its CONFIG — every shaping decision named, every named key actually applied. It does not prove the CONFIG values are well chosen, the swap is beautiful, or the timing is right; the scoring wave prices those.
