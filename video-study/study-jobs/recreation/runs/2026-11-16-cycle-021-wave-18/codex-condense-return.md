## 2 — Guard candidate (config-census): cure-site attack

**Forcing evidence — REAL.** T130's `config-census.md` filed HITs 0, resolving "geom.carW/carH → car scale declaration." **Diagnosed mechanism — WRONG, so the drafted cure misses the site.** The candidate claims "the leg's application-site resolution checked style/text sites and missed geometry-construction sites" and would amend `guards/guard-config-census.md` so resolution "must include geometry-construction sites (SVG attribute bindings + canvas geometry parameters)." The filed census contradicts the diagnosis: resolution did *not* omit the geometry keys — it listed them and accepted a **declaration** as their application site. Two mechanisms actually produced the miss, neither cured by adding a site category:
1. **Site-validity failure (§2 of the guard file).** The guard already requires every key to resolve "to at least one application site." T130's census satisfied that text with a nominal site — the key's own declaration, plus (for carW) an unrelated consumer (the puff midpoint). A category list that adds "geometry-construction sites" leaves the same author free to file "car scale declaration" under the new category and pass again. The defect is that *any reference counted as application*; the cure must require value-flow into the construction the key names.
2. **Declared-invariant exemption (§1 of the guard file, as applied).** The census's all-literal scan classified the car silhouette path coordinates and wheel offsets as DECLARED INVARIANTS and exempted them — the very literals that implement the car's size, standing outside CONFIG while `geom.carW/carH` promised that control. The candidate does not touch this exemption at all.

**Required re-encoding (the amendment lands on guard-config-census.md §2 + §1, not on a site-category list):**
> "§2 addendum: an application site counts only where the key's value flows into the construction of the subject the key names (carW/carH → the car body's path/transform and wheel geometry). A key whose only occurrences are its declaration, storage, or a consumer other than its named subject (e.g. carW read only by the puff-midpoint computation) is UNAPPLIED = HIT. §1 addendum: the declared-invariant classification is barred for any literal that implements a dimension a CONFIG key promises — if a geom.* key names it, the literals constructing it are subject-shaping and must read from the key. Forcing evidence: T130 (Cycle 021) — census HITs 0 with 'geom.carW/carH → car scale declaration' while carH occurred only in its declaration and the car path/wheels were hardcoded; reusability lens 68."

Naming geometry-construction sites as *examples* inside the value-flow rule is welcome; as the amendment's operative content it is AMENDMENT-THEATRE — prose naming a cure while the operative test (what counts as a site) stays unchanged.

**Verdict: config-census candidate — REVISE** (re-encode as above; the cure site is the guard's site-validity test + invariant exemption, in `guards/guard-config-census.md` §§1–2, with a consequential line in guards.md item 7's summary if its wording implies category coverage suffices).
