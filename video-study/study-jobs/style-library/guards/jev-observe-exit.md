# Jev call — jev-observe-exit (style-library)

_Per-call definition from jev-call-template.md. Built 2026-11-14 (phase-guard augmentation pass 1). The judgment: a registration pass may only plan against a landing inventory priced from the packets themselves — never from a hand-off's word — with tier state, Feeds state, and the consumption count read from the library's own files this cycle._

## 1. What it judges
- Deliverable / surface judged: the cycle's Observe working memory in RUN.md — the landing inventory (per-packet disk state), the current library counts, the tier state, and the demand signal — at the moment Observe would hand over to Plan.
- Call point: style-library INSTRUCTION §1, as its gate out. The phase advances on the verdict's recorded disposition (applied, or set aside with reason). An unfired call makes the cycle INCOMPLETE.

## 2. Instruction (the model's charge)
Judge whether this Observe working memory can support a registration Plan for THIS library. Price, in order: (1) LANDINGS PRICED FROM THE PACKETS THEMSELVES — every inventoried packet carries its own disk state (PDF present · md twin present · frames present), verified this cycle; a packet counted on its hand-off entry's word alone is unpriced, however confident the entry sounds. Packets whose state changed (in-flight → landed, scores filed against a technique) are named with the evidence that changed them. (2) TIER STATE READ FROM THE REGISTER — current tier counts (DESCRIBED · IN PROGRESS · RECREATED, printed separately, never merged) and the OWED / not-owed split are read from TECHNIQUES.md and its tier register this cycle, and any tier move pending this cycle is tied to the recreation/practice scores.md that evidences it — a tier move claimed from a lane report, a scores summary, or memory is not read, it is rumoured. (3) FEEDS STATE READ — the TECHNIQUES.md `Feeds:` fields were actually read, so the cycle knows which techniques feed which consumer views and whether anything this cycle will touch a Feeds field or a tier; where a change is coming, the VIEWS.md regeneration duty (Amendment A5: same cycle, or the deviation STALE-VIEW) is already visible in the inventory as a named obligation, not discovered in Verify. (4) CONSUMPTION HONESTY — production pulls since the last cycle are counted only from a production job's Observe record or an HQ-routed note, cited by path; the library's own naive-use test and any lane self-test never count; zero pulls prints as zero, beside the production counts, never omitted and never softened (growth = consumed + passing; consumption stood at 0 through 2026-11-13 and that zero is this call's baseline fact, not an embarrassment to route around). (5) DROUGHT AND DEMAND CONTEXT — if nothing landed, the inventory says so and names the queue state read from `../QUEUE.md` with scouting as the drought's owner; if GROWTH.md's days-to-clear has grown, that direction is in the inventory where Plan can price it. Score 0–1 per dimension and classify the primary defect. An inventory that cannot support the Plan returns; it never advances on hope.

## 3. Context contract (masked view)
- FED: the RUN.md Observe inventory as drafted (per-packet disk states · counts · tier state · pending tier moves with their scores.md paths · Feeds-touching items · consumption entries with their citing paths · queue state line) · the current TECHNIQUES.md header counts + tier register lines · the current CONSUMPTION.md pull count line · GROWTH.md's latest throughput line.
- NEVER FED: the registrar's rationale or confidence prose · a hand-off entry's characterisation of its own packet (the entry is a pointer; its adjectives are not evidence) · reception/popularity data (a popular packet is not a landed one) · prior cycles' counts as a substitute for this cycle's read.
- Ceiling: ≤32k tokens; text only. Packing rule: if the technique register exceeds the ceiling, fed the header counts + tier register + only the entries this cycle's landings touch — never truncate the landing inventory itself; an inventory too large to feed whole is itself a RETURN-TO-OBSERVE finding (the cycle is oversized, split it per INSTRUCTION §8).

## 4. Output space
- Verdict classes: **ADVANCE · ADVANCE-WITH-GAPS · RETURN-TO-OBSERVE**. ADVANCE-WITH-GAPS names each gap and the Plan step that must carry it; a gap in dimension (1) or (2) may never ride as a gap — those return.
- Dimensions (0–1): landing completeness (0.0 = packets counted on hand-off words · 1.0 = every landing disk-verified this cycle, state changes evidence-named) · tier-state fidelity (0.0 = tiers from reports or memory · 1.0 = counts + pending moves read from the register and their scores.md) · feeds-and-views awareness (0.0 = Feeds unread, VIEWS duty invisible · 1.0 = Feeds read, every coming Feeds/tier change carries its same-cycle VIEWS regeneration obligation) · consumption honesty (0.0 = pulls claimed from impressions, tests, or omitted when zero · 1.0 = every pull cited to an Observe record or HQ note, zero printed as zero) · drought/demand context (0.0 = a silent or unexplained inventory · 1.0 = queue state and days-to-clear direction named with their owners).
- Rejection taxonomy (one primary, on RETURN-TO-OBSERVE): UNPRICED-LANDING (a packet counted without its own disk verification) · TIER-FROM-REPORT (a tier state or pending move sourced from a report/memory, not the register + scores.md) · FEEDS-UNREAD (Feeds fields not read, so the VIEWS impact of the coming cycle is unknown) · PHANTOM-PULL (a consumption claim with no citing Observe record / HQ note, or a self-test counted as a pull) · STALE-COUNT (counts carried from a prior cycle or from memory instead of re-read this cycle) · SILENT-DROUGHT (zero landings recorded without the queue state and its owner).
- Accepted profiles travel: the dimension profile prints in RUN.md beside the gate line, and Plan inherits it — a low feeds-and-views score obliges the Plan to price the VIEWS work explicitly, a low consumption-honesty history obliges recount, not narrative.

## 5. Floors and disposition
- landing completeness < 0.7 → RETURN-TO-OBSERVE · tier-state fidelity < 0.7 → RETURN-TO-OBSERVE · consumption honesty < 0.5 → RETURN-TO-OBSERVE (a phantom pull is a faithfulness defect, not a gap).
- Disposition: the verdict is advisory — reviewed by the runner, applied or set aside with the miss recorded in Condense. The verdict, its primary class, and its disposition land in RUN.md either way.

## Call command
- Assemble the §3 context as one text packet (RUN.md inventory draft + the named register/consumption/throughput excerpts, ≤32k) and fire it through the fleet's sealed Jev decision-model route with §2 as the instruction verbatim; record the raw verdict, the dimension profile, and the primary class in RUN.md before Plan opens. Until that route is bound for this job, the runner executes this file's §2 + §3 as the defined prompt-and-context assembly. **Firing: this call fires at its step on every cycle. A cycle in which it did not fire prints INCOMPLETE.**
