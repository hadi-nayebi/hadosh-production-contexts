## 2. Instruction (the model's charge)
Judge whether this Plan, executed exactly as written, would produce a packet that passes §5 Verify and jev-packet — or whether it plans a defect in. Price, in order: (1) Segmentation grounding — does the segmentation model match the specimen's actual form from Observe (short ≤90 s: motion beats · long >90 s: musical/visual sections first, beats inside sections)? A beat-first plan for a long-form specimen, or a section plan with no section signals cited, is ungrounded — the founding specimen (198.41 s, 15 sections) is the anchor case. (2) Packet section plan — is every §3.3 section planned with its source and evidence route: (1) identity+technical · (2) consumer+ surface as a section OF THE PACKET written by its producer (Amendment A1 §2 — planning to name the consumer only at adoption repeats G2) · (3) technique catalogue (per entry: name · timestamps · mechanics · why · frame evidence) · (4) tempo map (per-section for long form) · (5) goods AND bads as a producer section with timestamp-bound pricing planned from the start (planning no goods/bads route repeats G1 — §6.6 makes it a hard Verify gate) · (6) lessons across every lesson class Observe named present (Amendment B1), each tagged class + consumer, mapped to containers with build-cost notes · (7) idea bank · (8) reception link with the "not yet run — charged" print planned when reception has not run (A1 §3 — silence in that slot is a completeness failure, G3's form)? (3) Execute checklist — does a named Execute checklist exist in RUN.md, complete against §3's steps (archive+probe → extract per the sampling/clip rules → write twin → render PDF from the same source → register hand-off), in execution order, each step checkable? Clip-ruling pricing (added 2026-11-15, Cycle-011 Condense, on that cycle's codex-condense ESCAPED verdict for this definition): the Plan must carry the per-entry clip ruling table of INSTRUCTION Amendment A6 — every catalogue entry that will make a motion/timing claim ruled clip / no-clip with its stills-sufficiency reason, temporal techniques (dissolve · zoom · morph · cut on action · match cut) defaulted to clip, and the extraction (timestamps + duration) named for every clip ruling. A Plan whose clip rule names only its positive cases prices this dimension down — that is Cycle-011's Finding 3 defect, priced one gate late in that cycle and priced here, at this gate, from now on. (4) Verify checklist — does a named Verify checklist exist in RUN.md, and does each item name an instrument, not an intention: the §5 completeness census, the ≥3-entry evidence-binding frame sample, the goods/bads honesty check, the naive-consumer test against OBJECTIVE's five tests, the own-eyes rule, the §6 guards, and the jev-packet call point with its exact-version receipt? A Verify item that says "check quality" with no instrument fails this dimension. (5) Failure points — does the Plan price what breaks it, for THIS specimen: archive/access failure and its route, probe disagreement, frame-sampling missing a technique's before/during/after, small on-screen text the evidence frames cannot resolve (A1's candidate per-entry paraphrase marking), captions contamination in extracted frames/clips (fleet law — delete and re-extract), tempo claims without timestamps, and the long-form split (§8/§2.4: split by section at Plan, continuation queued by name — a split absorbed silently is a reduction)? (6) Reductions — does the Plan name anything it quietly drops from the objective (sections deferred, clips dropped, lesson classes unplanned), with the drop's return address? An unnamed drop is the defect; a named split with a queued continuation is lawful. Score each dimension 0–1, classify by the taxonomy (one primary by precedence), and return the verdict the floors compose. You judge text paperwork only.

## 3. Context contract (masked view)
- FED: RUN.md Plan section (segmentation model · extraction plan · section plan · Execute checklist · Verify checklist · failure-point evaluation · split decision) · RUN.md Observe product + the jev-observe-exit receipt/profile for this cycle · INSTRUCTION §3.3's eight-section form · OBJECTIVE's five cold-reader tests.
- NEVER FED: the planner's rationale prose about the plan's elegance · any Execute output (the plan is judged before execution) · prior verdicts on this plan.
- Ceiling: ≤32,000 tokens text. Packing rule: checklists first, section plan second, failure points third; overflow = preflight FAIL, never a silent trim.
- Output must validate against the call's local output schema (verdict + dimensional scores + one primary classification + evidence pointers); malformed output = protocol failure, not a verdict.

## 4. Output space
- Verdict classes: **EXECUTE · REVISE · RETURN-TO-OBSERVE**. REVISE = the Plan is repairable inside Plan (checklist or failure-point gaps); RETURN-TO-OBSERVE = the Plan's defect is a context defect (segmentation ungrounded in the media, consumer or lesson classes the Observe never established).
- Dimensional scores (0–1; anchors: 0.0 = absent/false · 0.5 = present but partial or instrument-less · 1.0 = complete and executable as written):
  - segmentation grounding
  - packet-section completeness (all eight §3.3 sections planned with sources)
  - execute checklist completeness
  - verify checklist instrumentality (instrument named per property, incl. the jev-packet receipt)
  - failure-point evaluation
  - reduction honesty (drops named with return addresses, or explicitly none)
- Rejection taxonomy (one primary, by this precedence): SEGMENTATION-UNGROUNDED · SECTION-PLAN-INCOMPLETE · NO-EXECUTE-CHECKLIST · NO-VERIFY-CHECKLIST · FAILURE-POINTS-ABSENT · QUIET-REDUCTION · SPLIT-UNRECORDED.
- Accepted profiles travel downstream: the dimensional profile + receipt are cited in RUN.md's Execute section; Verify checks the deliverable against this Plan's checklists, and Condense prices checklist misses against this profile.

## 5. Floors and disposition
- Floors: execute checklist completeness < 1.0 on existence (no checklist, no Execute) → REVISE minimum · verify checklist instrumentality < 0.5 → REVISE · segmentation grounding < 0.5 → RETURN-TO-OBSERVE · any §3.3 section unplanned (dimension < 1.0 on presence) → REVISE, except §3.3(5) goods/bads or §3.3(2) consumer unplanned → REVISE with the G1/G2 class named in the receipt (these two sections failed at Verify in Packet #1 precisely because no Plan priced them) · any dimension < 0.4 → REVISE or RETURN per its class · all dimensions ≥ 0.7 with both checklists standing → EXECUTE.
- Disposition: the verdict is advisory — reviewed by the runner, applied or set aside with the miss recorded in Condense. The verdict + receipt land in RUN.md either way.
