## 1. opus-visual-motion-engine — Lob0Garou

- **URL:** https://github.com/Lob0Garou/opus-visual-motion-engine · SKILL.md at `blob/HEAD/SKILL.md`
- **What it is:** A single-skill system that turns a text-only or multimodal agent into a motion-graphics studio producing one self-contained HTML file per piece, rendered to MP4. MIT. Created 2026-09-25 (per repo), 4 stars at crawl — small, but the most complete single-file doctrine found in this harvest.
- **Structure:** SKILL.md in 14 numbered sections (§0–§13) plus a composition template and scripts. §0 "Read first" is unconditional: a references table keyed by deliverable type must be read before any work. §1 Gather → written **PLAN.md** (sources, a named direction, scene cards, a handoff table, one signature moment, global timeline, sound plan). §2 Build from `assets/composition-template.html`. §3 Deterministic time. §4 Motion grammar. §5 Stack decision. §6 Technical floor. §7 Anti-template tells (a table of tells → fixes). §8 Render + QA (mandatory). §9 Critique loop. §10 Sound. §11 Export. §12 Delivery. §13 Side effects / rights.
- **Determinism techniques:**
  - The composition is built from a fixed template: a 1920×1080 stage exposing `window.DURATION`, `seek(t)`, `render(t)`, a `SCENES` array and a `HANDOFFS` table. The template's ENGINE blocks are immutable; the agent fills only marked EDIT blocks.
  - §3 bans `setTimeout`, CSS animations, unseeded `Math.random()`, and `Date.now()` as time sources; randomness only via a seeded `mulberry32` PRNG and a `hash01` helper shipped in the template.
  - Motion is vocabulary-constrained (§4): every move must be one of ENTER / EMPHASIS / TRANSITION / CAMERA / HANDOFF; the default crossfade is banned.
  - **Metadata lives inside the HTML file:** the sound design is a deterministic cue sheet embedded as `<script type="application/json" id="score">` inside the composition, and an audio-analysis step (`audio-data.mjs`) injects measured beats/onsets/RMS as `window.AUDIO` into the same file. The plan (PLAN.md) is a sibling file, but the score, the audio data, the scenes and the handoffs are all inside the one HTML source.
- **QA / verification gates:**
  - §8 is a scripted frame battery, `scripts/qa.mjs`, which **exits 1 on FAIL**: frozen-timeline detection, dead-air detection, a determinism check (revisit frames out of order and compare), glyph-ink text collision/clipping measurement, a handoff contact sheet, contrast measurement, dash-snap checks, and template-tell detection. Outputs `report.md` / `report.json`, a contact sheet, moment stills and handoff sheets.
  - §6 technical floor is numeric: single HTML < 16 MB, design tokens only, contrast ≥ 4.5:1, no text under 20px at 1080p.
  - §9 critique loop: 11 concrete questions the agent must answer against the QA outputs; a text-only model judges from `report.json` (ink coverage, frame diffs) rather than from looking — the skill is explicitly designed to work for an agent that cannot see.
  - §12 delivery rule: deliver plan + QA verdict + critique; **state what was NOT verified; never claim a check that was not run.** Expect 2–3 generations before a pass.
  - Sound: `score.mjs` renders the embedded cue sheet to audio at −14 LUFS / ≤ −1 dBTP; export via `export.mjs` is frame-exact ffmpeg.
- **Assumptions about the agent:** Assumes the agent may be text-only (all verification is available as JSON numbers, not just images); assumes it will improvise unless the template, the vocabulary and the bans physically constrain it; assumes 2–3 failed generations are normal.
- **Demonstrated output:** `examples/brand-reel.html` — a 15 s reference reel (7 scenes, 6 handoffs) passing its own QA at 0 WARN. A benchmark against the HyperFrames skill suite on the same 9,226-character prompt and the same DeepSeek harness (deepseek-v4.1-flash, 2026-09-25): 27.6 min vs 98.7 min, 68 vs 147 steps, 22 QA runs (final PASS) vs 0. Caveats stated by the author: single run, and the two outputs had different specs (1080p30 no audio vs 4K60 with audio), so the comparison is indicative, not controlled.

## 2. frame-motion — venthewise (Paolo Libertad)

- **URL:** https://github.com/venthewise/frame-motion · SKILL.md at `blob/main/SKILL.md`
- **What it is:** A single-file-scene motion skill: each piece is one HTML page driven by a `seek(t)` contract, rendered by a bundled Python driver. MIT, created 2026-10-18, v3.0.0, 3 stars at crawl.
- **Structure:** A strict rendering contract, then a 10-step workflow: Brief → Beat map → **Four key stills (approval gate)** → Draft (half-res) → Checks → Critique loop → Final render → Audio → Mux → Deliver.
- **Determinism techniques:**
  - The contract is one function: `window.seek = async (t)` must draw the **entire** frame for time *t*. No `Date`, no timers, no `requestAnimationFrame`, no accumulated state. Seeded PRNG only. All assets local or data-URI (works offline). The renderer additionally hardens the page by pausing CSS animations.
  - Any engine may sit under the contract — GSAP, Lottie, anime.js, WAAPI, Canvas, WebGL, SVG, `<video>` — but all of them are driven from `seek(t)`, never free-running.
  - The beat map is a table: BPM and scene changes locked to downbeats before anything is built.
- **QA / verification gates:**
  - **Pre-production gate:** four key stills must be approved before the draft exists.
  - `scripts/render.py` subcommands form the battery: `probe`, `poster`, `sheet` (contact sheet), `beats`, `draft`, `full`, `parallel`, `pops` (frame-diff spikes, each tagged on-beat or off-beat), `loop` (checks position **and velocity** continuity at the loop seam), `determinism` (seek a, b, a — the two *a* frames must be pixel-identical), plus audio `render / peak / drop / tempo / cuts / loudnorm / mux`.
  - Critique loop scores 7 axes 1–10 (Hook, Readability, Motion quality, Continuity, Rhythm, Originality, Loop/ending) and iterates until **all axes are ≥ 8**; the scores and the single biggest fix are written down each round.
  - Final render uses motion blur by construction (`--sub 3..8 --shutter 0.5` sub-frame sampling). Audio is code-synthesised, with peak/drop/tempo **measured**, normalised to −14 LUFS.
  - Anti-generic rules: one concept, one typeface, ≤ 3 colours plus black/white, no default gradients/glows/particles/crossfades, no holds longer than ~0.5 s, illustrative numbers must be labelled as illustrative.
- **Assumptions about the agent:** Assumes the agent can run Python/ffmpeg tooling and read contact sheets; assumes approval of stills is cheap and approval of finished video is expensive, so the gate sits on stills.
- **Demonstrated output:** `examples/kinetic-title.html` ("NIGHT TRAIN", 4 s, 120 BPM) with its contact sheet shown in the README; `examples/audio-template.html`; a test suite in `tests/test_beats.py`.

## 3. motionmaxxing — Tejashmakwana (Tejas Makwana)

- **URL:** https://github.com/Tejashmakwana/motionmaxxing · README and SKILL.md both read in full.
- **What it is:** A motion-direction skill (ships inside "FinalMotion") whose craft rules are **measured from real professional films** rather than asserted. Apache-2.0, created 2026-10-06, ~1,450 stars / 151 forks at crawl — the most-starred craft-first skill in this harvest.
- **The evidence base (stated in SKILL.md):** 53 frame-accurate professional moments decoded by 6 parallel AI analysts and human-reviewed into ~150 WHEN/DO/BECAUSE rules over ~4,288 measured moves, 12 measured easing curves, 52 ranked human films, ~30 AI films judged blind, plus the author's own verdict log (`taste/verdicts.md`, `taste/edits.md`) which the skill reads at the start of every job. Measured numbers it teaches: median move ≈ 10 frames; landings decelerate (58% ease-out family); overshoot < 9%; nothing grows from zero; 3,392 transform entries vs 584 opacity fades in the corpus; 96% hard cuts; end hold 0.6–1.4 s.
- **Structure — 10-step protocol:** 0 Toolbox/taste (`providers.sh` capability probe; read the taste files) → 1 Know the brand (`brand.mjs` captures colours/fonts/screens from the URL; `fetch_logo.mjs` fetches the **official** logo — never redraw it) → 2 One true thing + PAGE (Problem/Audience/Goal/Emotion in four lines) → 3 Find the idea (≥ 3 ideas of different kinds; cover-the-logo test: if the film still works for a competitor with the logo covered, the idea fails) → 4 World & time: `STORYBOARD.md` with per-act ground/light/depth/texture/sound, a beat table where every beat states what belief it "buys", and gates G1/G3/G4 pre-checked **on paper before building** → 5 Script/voice (optional; `sync.mjs` converts word timings to frame-accurate beats — on-screen words land 0–2 frames before they are heard) → 6 **Hardest beat first** (build the hero moment and its hardest handoff, render stills, look, fix the idea before building the rest) → 7 Look honestly (`look.py`, `lint.mjs`) → 8 Sound to picture → 9 Deliver `final.mp4` + the editable `index.html` + `NOTE.md`.
- **Determinism techniques:** A vendored runtime (`runtime/motion.js` on GSAP, GSAP/Three.js vendored — no CDN) in which every frame is a pure, seek-safe function of time; the 12 measured easings are available **by name** so the agent picks from measured curves instead of inventing beziers; `Motion.selfTest` must report zero mismatches. Templates: `templates/film.html` is copied as the starting file.
- **QA / verification gates (G0–G5):** A failed gate is fixed, never argued; the numbers are quoted in `NOTE.md`.
  - G0 render exists, decodes, moves, length matches plan, audio present if planned — `look.py`.
  - G1 proof readable — **by eye, no script, and the skill says so** (never estimate a number).
  - G2 no run of > 3 consecutive flat frames — `look.py`.
  - G3 end hold ≤ 1.4 s and final shot ≤ 25% of the film — `look.py`.
  - G4 one hero per frame — by eye.
  - G5 no page chrome — `lint.mjs` with named rules (C1–C7 corner labels/counters/timecodes, D1 deck layout, P1 progress bars, T1 typed headlines, V1–V5 vibe-coded UI cards); exit 1 on fail.
  - The "Never ship" list (12 items) includes self-certification itself: a delivery without `NOTE.md`, or with gates claimed without script numbers, is a fail. The agent **never certifies the film as good** — it describes what it checked. Known limits are stated plainly (lint cannot see text inside canvas/images; G1/G4 are by-eye; WebGL renders at 7–11 fps).
- **Assumptions about the agent:** Assumes the agent's default output is "AI slop" with named, enumerable tells (a 25-pattern slop autopsy in `references/slop.md`); assumes taste must be supplied as measured precedent (`library/moments.jsonl`, 716 rule-only precedent rows queryable per beat via `precedent.py`) plus a persistent per-user verdict log.
- **Demonstrated output:** Three before/after MP4 pairs linked in the README (Cluely, Spotify, Wispr Flow — same model, same brief, with vs without the skill) and a hero MP4 made with the skill's own runtime; example films in `examples/` including a runtime self-test page that must print PASS.

## 5. OpenMontage — calesthio / OpenMontageInc

- **URL:** https://github.com/calesthio/OpenMontage · `AGENT_GUIDE.md` read in full (1,144 lines).
- **What it is:** Not a single skill but an instruction-driven production system: the agent **is** the intelligence and orchestrator; Python exists only as tools + persistence; there is deliberately no orchestration code. AGPL-3.0.
- **Structure — Rule Zero:** Every production MUST go through a pipeline, no exceptions: identify the pipeline in `pipeline_defs/`, read its YAML manifest, run preflight, then execute stage by stage, reading that stage's director skill (`skills/pipelines/<pipeline>/<stage>-director.md`) **before** doing the stage's work, and reading Layer-3 vendor skills (`.agents/skills/`) before calling any tool that declares `agent_skills`. Ad-hoc scripts and skipping checkpoints are forbidden. Stages: research → proposal → script → scene_plan → assets → edit → compose. 12 pipelines are listed (animated-explainer, talking-head, screen-demo, clip-factory, podcast-repurpose, cinematic, documentary-montage, animation, character-animation, hybrid, avatar-spokesperson, localization-dub, plus a framework smoke test); beta pipelines are flagged as unaudited.
- **Determinism / anti-improvisation techniques:**
  - Each stage produces **one canonical JSON artifact validated against a schema** in `schemas/artifacts/`. Checkpoints live at `projects/<id>/checkpoint_<stage>.json`, and the gate is enforced in code (`lib/checkpoint.py`): a gated stage cannot be written `completed` without `human_approved=True`; the proposal checkpoint additionally requires an approved proposal packet. Approval is per-gate — an early "go ahead" never covers later gates.
  - **Decision Communication Contract:** before any paid call the agent must announce tool, provider, model, reason, and whether it is a sample or a batch; major changes (provider, model, runtime, dropping narration, sample → batch) require asking first. The decision log is append-only: a changed decision is appended as a new entry with the same (category, subject) pair, with the superseded option recorded in `options_considered`.
  - **Hard rule on runtime choice:** when both Remotion and HyperFrames are available, the proposal MUST present both, with brief-specific pros/tradeoffs and a recommendation, and wait for approval; a silent default is forbidden. Once chosen, `render_runtime` is locked and carried unchanged through every later stage; a silent swap is forbidden, and hitting a blocker requires a structured escalation (what was attempted / what failed / failure type / options / recommendation).
  - **Authoring modes:** Templated (stock `cut.type` scene types) vs Atelier (hand-authored from scratch; the default for hero work; stock components are off-limits as looks and may only be read as a mechanics codex). Atelier carries a distinctness review: "could this be any other product's video?"
  - **Motion-required rule:** a still-image / Ken Burns fallback is forbidden when the brief depends on motion.
  - **Preflight:** `provider_menu_summary()` is mandatory — present the capability menu as "X of Y configured", group setup offers by environment variable, classify passed/degraded/blocked; no production until the user understands the capability envelope. A music plan is mandatory at proposal stage.
  - **Reviewer protocol:** a meta-skill (`reviewer.md`) runs after every stage, max 2 rounds, findings graded critical / suggestion / nitpick; critical findings must be fixed and re-reviewed.
- **Assumptions about the agent:** Assumes the agent will skip process under time pressure unless the process is enforced by code checkpoints and schema validation; assumes paid generation calls are the irreversible step and concentrates its communication contract there. Project convention: `projects/<name>/artifacts|assets|renders/final.mp4`; a "Backlot" board observes progress but never blocks.
- **Demonstrated output:** The repo itself is the artifact (pipeline definitions, schemas, checkpoint library, stage-director skills). The AGENT_GUIDE read for this study does not itself link shipped films, so no film-level capability claim is recorded here.

## 6. remotion-best-practices — remotion-dev/skills (official Remotion skill)

- **URL:** https://github.com/remotion-dev/skills · SKILL.md read in full via a mirror that reproduces the full skill text (aimarketly). Install: `npx skills add https://github.com/remotion-dev/skills --skill remotion-best-practices`. Install counts on skills.sh are claimed at 350k–401k depending on source/date — treated here as claimed, not verified.
- **What it is:** The vendor's own **knowledge skill**, not a production pipeline: it teaches the agent correct Remotion API usage and routes to ~32 on-demand rule files (`rules/*.md`: subtitles, ffmpeg, silence-detection, audio-visualization, sfx, 3d, audio, calculate-metadata, compositions, fonts, durations via Mediabunny, gifs, images, light-leaks, lottie, html-in-canvas, measuring-dom/text, sequencing, tailwind, text-animations, timing, transitions, transparent-videos, trimming, videos, Zod parameters, maplibre, ElevenLabs voiceover).
- **Core instructions:** Scaffold with `npx create-video@latest --yes --blank --no-tailwind`. Animate **only** with `useCurrentFrame()` + `interpolate()` / `Easing.bezier`, always clamped. **CSS transitions/animations are forbidden; Tailwind animation classes are forbidden.** Assets go in `public/` and are referenced with `staticFile()`; media via `<Img>`/`<Video>`/`<Audio>` from `@remotion/media`. Timeline structure via `<Sequence from durationInFrames>`; the Composition is declared in `Root.tsx` (width/height/fps/durationInFrames); dynamic duration/props via `calculateMetadata`; props typed with a Zod schema (in the parameters rule).
- **Determinism techniques:** Determinism is implicit in frame purity — every frame is a function of the frame number, so wall-clock and stateful animation are excluded by the API rules above. (Notably, this mirror's text does not itself spell out `Math.random()`/`Date.now()` bans; forks/mirrors of the same skill do state them explicitly — e.g. "Never use Math.random() or Date.now(), never useState/useEffect". The difference between the canonical text and its copies is itself a finding about this ecosystem: the rule everyone cites is not in the canonical file everyone installs.)
- **QA / verification gates:** Weak by design — a single **optional** one-frame still check (`npx remotion still --scale=0.25 --frame=30`), with "skip it for trivial edits" as the stated guidance. There is no render-verify loop, no gate, and no delivery checklist. This is the clearest contrast in the harvest: the most-installed video skill has the thinnest verification of any serious source read.
- **Assumptions about the agent:** Assumes the agent's failure mode is API misuse (wrong props, unclamped interpolation, CSS animation habits imported from web dev), not design or verification failure.

A creator-edit-phrase table maps the user's edit language ("make the logo bigger at the end") to the required domain-skill combinations.
  - CLI freshness discipline: probe the pinned version (`npx hyperframes@latest upgrade --project . --check`); if bumped, verify with `hyperframes check` after the bump; never leave a bumped pin unverified; name old and new versions in the report.
  - Studio/desktop: open the Studio preview before the delivery render in every mode.
- **Determinism techniques:** Lives in core (source 8); the entry skill's contribution is **decision determinism**: one routing artifact (BRIEF.md), first-match tables instead of judgment calls, and state-resume instead of re-interview.

- **Demonstrated output:** The framework repo and its Studio; per-workflow outputs are in the workflow skills, not this entry file.

## 8. hyperframes-core — heygen-com/hyperframes — **READ IN LARGE PART (~80%); TAIL UNREAD**

- **URL:** https://github.com/heygen-com/hyperframes (skill `hyperframes-core`) · Read via the skill4agent mirror, lines 0–911 of 1,140; the remainder (911–1,140) could not be re-fetched (the mirror URL returned 404 on re-open). The Non-Negotiable Rules below were confirmed in the read portion and in the same mirror's indexed excerpt. The separate `references/determinism-rules.md` file was **not** opened; claims about it are limited to the routing table that names it.
- **What it is:** The technical contract for HyperFrames compositions — the deterministic core under the whole ecosystem.
- **Contract (from the read portion):**
  - A composition is an HTML file; the DOM declares timing with `data-*` attributes. There is exactly **one** `gsap.timeline({paused:true})`, registered at `window.__timelines["<composition-id>"]`, built **synchronously** at page load. Render duration comes from the root's `data-duration`, **not** from the timeline's length.
  - Structure rules with silent-failure warnings: a standalone root must NOT be inside `<template>`; a sub-composition root MUST be inside `<template>`; everything outside the template (head/styles/scripts) is discarded for sub-compositions; the host id must exactly equal the inner composition id and the timeline key (no `-mount`/`-slot`/`-host` suffixes); the root must be explicitly sized or content collapses to the top-left — a silent bug that lint/validate/inspect do **not** catch; ≥ 80px padding as a title-safe margin.
  - **Non-negotiable rules:** no `Math.random()` / `Date.now()` / `performance.now()` driving visuals (seeded PRNG instead); no `repeat: -1` — use `repeat: Math.max(0, Math.floor(duration / cycleDuration) - 1)` (floor, not ceil — ceil overshoots `data-duration` and trips the `gsap_repeat_ceil_overshoot` lint); no tweening `display`/`visibility`; no `gsap.set` on later-scene clips; animate only a visual-property allowlist; no `<br>` in body text; transformed elements must be block-level and sized; `<video>`/`<audio>` must be a direct child of the host root, never inside a sub-composition template or wrapper; the framework owns media playback (no `.play()` / manual `currentTime`).
  - Routing table to 19 reference files (minimal-composition, composition-patterns, data-attributes, tracks-and-clips, sub-compositions, variables-and-media, determinism-rules, full-screen-motion, tailwind, …) — the skill is an index over a rule library, loaded on demand.
- **Assumptions about the agent:** Assumes the agent writes plausible GSAP that silently breaks a seek-based renderer; the contract therefore enumerates failure modes (including which ones its own tooling cannot detect) rather than teaching GSAP generally.

## 9. HyperFrames motion-graphics workflow — doitian/video-agent copy

- **URL:** https://github.com/doitian/video-agent/blob/HEAD/.agents/skills/motion-graphics/SKILL.md · Read in full.
- **What it is:** The HyperFrames `/motion-graphics` workflow skill as carried in a third-party agent repo — notable because it is written for **autonomous** execution (subagent dispatch, resume-from-disk), unlike the router in source 7. Scope is tightly bounded: a short, design-led, **unnarrated** motion graphic < 10 s (up to ~30 s); motion is the message. Longer, narrated or multi-scene work routes to `/general-video`; unclear requests route back to `/hyperframes`.

## Leg A findings

### The five strongest transferable techniques

**1. Determinism by construction: the frame is a pure function of time, and the bans are identical everywhere.**
Every serious source independently converges on the same contract, in three dialects: Remotion's `useCurrentFrame()`, HyperFrames' single paused GSAP timeline registered on `window.__timelines`, and the single-file school's `window.seek(t)` / `render(t)` that must draw the entire frame. The prohibitions are word-for-word the same across authors who show no sign of copying each other: no `Math.random()` (seeded PRNG only — mulberry32/hash, or Remotion's `random(seed)`), no `Date.now()` / wall clock, no CSS animations, timers or `requestAnimationFrame` as the timeline, no infinite repeats (HyperFrames even specifies the finite-repeat formula, floor not ceil). Two sources go further and **verify determinism itself**: frame-motion's `determinism` check (seek a, b, a — pixel-identical) and opus's out-of-order revisit comparison inside its QA battery. Transferable form: state the contract once, ban the named escape hatches, and add a determinism probe to the battery — do not rely on the instruction alone.

**2. Decisions are locked into a file before building, and the file — not the conversation — is what the builder reads.**
This is the ecosystem's universal pre-production gate, in escalating strengths: HyperFrames' `BRIEF.md` as the *only* routing artifact (nothing downstream re-opens the intent skill); charlie947's `brand.md` + `MOTION.md` read-first rule injected into CLAUDE.md; opus's PLAN.md with scene cards and a handoff table; OpenMontage's schema-validated stage artifacts with **code-enforced** human-approval checkpoints and an append-only decision log; doitian's `shot-plan.json` as a schema'd intermediate representation between planner and builder subagents; talkcraft's SHOTBOOK layer matrix with its mandatory "unfinished / uncollected" section. The strongest version (OpenMontage) doesn't trust the instruction — the checkpoint literally cannot be marked complete in code without the approval flag. Transferable form: a written plan artifact with a schema, a gate that blocks the build stage, and decisions recorded in a log that can only be appended to.

**3. Recipe libraries with demo-source-as-truth replace improvisation.**
Shotcraft (124 cards) and talkcraft (108 cards) are built on the same discovery: an agent told a recipe's *name* will produce a plausible, degraded imitation; an agent forced to copy the recipe's **actual demo source** inherits its tuned parameters. Both mechanise it — shotcraft requires reading the exact demo TSX and forbids downgrading the card's known-pitfall parameters; talkcraft adds `card_lint.py`, which checks that the copied file exists and is still ≥ 0.55 similar to the template (re-skinning allowed, motion-rewriting fails). Motionmaxxing reaches the same place from measurement instead of code: ~150 rules and 716 precedent rows distilled from 53 professionally made films, queryable per beat. HyperFrames' registry blocks (reuse-first, hand-author only the gaps) are the platform version. Transferable form: a library of named, parameterised, *runnable* recipes; selection by machine-filtered candidates with recorded rejection reasons; fidelity of the copy checked by a script.

**4. Frame-verification batteries are scripted, numeric, and exit non-zero — and the honest ones label what is still by-eye.**
The mature skills never let "it rendered" stand in for "it is right": opus's `qa.mjs` (glyph-ink collisions, dead air, frozen timeline, handoff sheets, template tells — exit 1 on FAIL); frame-motion's pops/loop/determinism probes plus a 7-axis critique loop that iterates until every axis scores ≥ 8; motionmaxxing's G0–G5, where scripted gates print numbers that must be quoted in the delivery note and the two by-eye gates are explicitly declared unscripted ("never estimate a number"); iart's stills→inspect→encode loop with an ffprobe assertion on the finished file ("renders lie; the file doesn't"); talkcraft's six machine gates including a freeze *predictor* run on stills before paying for a master render, and an SFX audibility check re-run on the delivered file because "the agent cannot listen". Layered on top in the two Vincentwei1021 skills: an **independent final review by a clean-context subagent** given an evidence pack and required to cite frame numbers — with talkcraft explicitly forbidding a fork of the maker's context as the reviewer, because that closes a self-proving loop. Transferable form: a battery of small, single-question scripts with thresholds; contact sheets as the review surface; delivery notes that quote the numbers and state what was not verified (opus's §12 and motionmaxxing's NOTE.md both mandate exactly that).

**5. Real material, closed fact sets, and word-timing as the single source of time truth.**
Three rules recur wherever output quality is demonstrated rather than claimed.
