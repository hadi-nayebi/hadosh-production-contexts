# LEG C — DETERMINISM ENGINEERING
## Deep study: HTML-assembly motion-graphics machine — 2026-11-08

**Job · Phase:** Research leg C of the motion-graphics study · Observe (field research) feeding Plan.
**Governing context:** The one-HTML law — *“a piece's production context is ONE growing HTML file that produces/shows the video — transcript, metadata, and reasoning behind EVERY choice live INSIDE it”* (`~/MEMORY.md`, “ONE HTML FILE PER PIECE — THE METADATA LIVES INSIDE IT”, 2026-10-29). Determinism is therefore not a render-export nicety: the same HTML is the workspace, the decision table, the player, and the render source. Any non-determinism in capture, keying, timing, serving, or provenance corrupts all four roles at once.
**Method:** Local record first (bounded, capped probes per `bounded_probe_discipline` skill; every local claim below cites its record file), then primary field sources (official docs, specs, source code, peer-reviewed / canonical papers) opened or searched — never snippet-only where a doc page exists.
**Cost line (per AGENTS.md common-sense gate):** full-file reads planned: ~10 load-bearing records + capped excerpts of ~8 more · agents spawned: 0 · the specific risk this pass retires: five recurring defect classes being re-diagnosed from scratch each version (v130→v155) instead of being engineered out once.

**Headline finding, in one sentence:** Our machine already discovered — by measurement, painfully, version by version — the *shape* of almost every cure the field uses; what it has not done is move those cures from *verification-time detection* (censuses, gates, watches) into *construction-time guarantees* (pure pose function of an integer frame, alpha-correct pipeline as the only resize path, forced-aligned locked timing table, content-hashed served URLs, signed provenance manifest). The field's pattern is uniform: **make the bad state unrepresentable, then verify the invariant cheaply** — we currently make the bad state freely, then verify expensively.

## (a) Realtime-capture frame drops / capture instability + Chrome headless trapping (SIGTRAP rc 133)

### OUR measured state

1. **Realtime playing passes systematically miss short beats.** `order-cv-measurements.md` (2026-11-05, serve build v130): a real-time Chrome run over CDP, sampled every 25 ms (194 samples, clock 0→5.05 s), saw **25/29 beats advancing**. The 4 misses were not defects in the film — they were sampling-cadence misses: ball cells 4, 5, 7 have windows **0.09–0.12 s** wide and “the busy main thread stretched the effective sampling gaps past them”; the claim settle pulse's ≥1.09-scale window is **~0.07 s** wide and no sample landed in it. All four had to be rescued by a second, different instrument — the scrub-path threshold map (33/33 intervals confirmed by probing both sides of every boundary through `rnPose`). So one verification question (“did every beat happen?”) already needs two instruments because the first is non-deterministic.
2. **The pose function itself is already pure — the capture is not.** `segment-fix/diagnosis.md` (v137): “Pose function `rnPose(t)` drives every element from the transport scrub; captures were made by scrub-seeking that same pose function in chrome-headless-shell (private port 9341, window 390×844, CSS transitions frozen so each capture is the exact pose of its t).” That scrub-seek path is deterministic. The *playing* path (rAF + page clock + audio) is the one that drops, jitters, and disagrees: the player gate records a standing tolerance because “the transport progress strip jitters ≤ ~84 px between same-build captures” (`top10/fix-player-record.md`, Phase P pixel guards) — i.e. even byte-comparing captures of the *same build* needs a fudge region.
3. **Audio advance is the flakiest gate assertion.** Served v154 gate: 59/71 pass, first failure “A5 audio playing and advancing ≥0.5 s” — audio `currentTime` advanced only **0.17 s** in the window (`top10/fix-player-gate-v154-served-output.json`). The local v155 gate file is worse on its face (59/210) with A5 audio at 0.00 s advance (`v155-gate.json`) — realtime media clocks in headless shells do not advance like wall clocks, so a gate written against realtime advance manufactures failures that are environmental, not film defects. FREEZE-v154's re-grade face names this honestly: “player-gate residuals identical on the v154 control (A5 environmental)”.
4. **Chrome headless shell traps on launch in agent sessions.** Standing machine note (`~/TOOLS.md`, 2026-11-05 ~23:50 EST): “Chrome headless shell also traps (SIGTRAP, rc 133) on any real launch from the main session since ~23:30 EST (`--version` still works).” AGENTS.md adds the concurrency lesson (2026-10-24): a shared debugging port (9333) let a parallel job's navigation kill another job's render mid-line — hence the standing rule *every render job gets a PRIVATE Chrome port* (v155 build record uses ports 9411–9416, gate on its own port 9367; segment-fix used 9341; fix-player gate 9367 — the rule is followed, but each record re-invents the launch).
5. **What already works locally:** fresh profile per gate run, private port per job, touch hit-testing instead of `.click()`, reachability proved before effect (`top10/fix-player-record.md` — 62/62 assertions, run 13, v148). That gate discipline is genuinely good; it is the *time model* underneath it that is realtime.

### The field's cure

- **Virtual time, not wall time.** Chrome's own headless reference: `--virtual-time-budget` “acts as a ‘fast-forward’ for any time-dependent code … forces the browser to execute any of the page's code as fast as possible while making the page believe that the time actually goes by.” — https://developer.chrome.com/docs/automation-and-testing/headless-cli
- **Deterministic mode is a first-class Chromium feature.** Chromium source (`headless/app/headless_shell_switches.cc`) defines `--deterministic-mode` (“put the browser into deterministic mode where begin frames should be issued over DevTools Protocol”), `--enable-begin-frame-control`, `--deterministic-fetch` (“network fetches complete in order of creation — removes a significant source of network related non-determinism”), and documents virtual time: “For determinism virtual time does not advance while there are pending network fetches.” — https://github.com/chromium/chromium/blob/e5b65ca9b408d525f787a946448b206f7f81cca9/headless/app/headless_shell_switches.cc
- **Atomic frame stepping via CDP.** `HeadlessExperimental.beginFrame` “sends a BeginFrame to the target and returns when the frame was completed. Optionally captures a screenshot from the resulting frame. Requires that the target was created with enabled BeginFrameControl. Designed for use with `--run-all-compositor-stages-before-draw`” — i.e. layout→paint→composite→screenshot as one atomic step at a caller-supplied `frameTimeTicks`, default interval 16.666 ms. — https://github.com/wirepair/gcd/blob/v1.0.3/gcdapi/headlessexperimental.go (generated from the CDP schema)
- **The production HTML→video tools are all seek, never play.** The code-rendered-video pattern, stated plainly: “The whole game is `time = frame / fps`. Every frame is a pure function of its frame index. The renderer *seeks* to a timestamp and screenshots — it doesn't play in real time and record… same input → same output, byte-stable.” — https://github.com/zvoque/docs/blob/HEAD/code-rendered-video-playbook.md . HyperFrames (HeyGen, HTML-native, closest to our machine): “The renderer **never calls play()**. It calls `seek(0)`, screenshots, `seek(1/30)`, screenshots…” with `HeadlessExperimental.beginFrame` for atomic capture on Linux, local fonts, time quantization, no `Date.now()`, no unseeded `Math.random()`. — https://github.com/simplearyan/studio-pro/blob/HEAD/docs/hyperframes/README.md
- **Remotion's determinism contract (official docs):** a frame must be a pure function of frame number; async readiness is explicit — `delayRender()` “pauses the render to let an asynchronous task complete”, `continueRender(handle)` releases it, un-cleared handles fail the render after a timeout instead of capturing a half-loaded frame. — https://www.remotion.dev/docs/delay-render/
- **Deterministic clocks in test tooling.** Playwright's Clock API: `install` / `pauseAt` / `fastForward` / `runFor` override `Date.now`, timers and rAF so time is “ticked through manually, firing all the timers consistently” — the test-world equivalent of virtual time. — https://playwright.dev/docs/clock
- **Launch robustness in containers (the SIGTRAP class).** The recurring production causes are environment, not page: `/dev/shm` defaults to 64 MB in containers and Chrome starves/crashes; cures are `--shm-size=1–2g` or `--disable-dev-shm-usage` (Chrome writes to /tmp instead), plus `--no-sandbox` / `--disable-setuid-sandbox` when running as root without kernel sandbox capabilities, pinned browser builds, and the *same* container image locally and in CI so launches are reproducible. — https://dev.to/dennis-ddev/puppeteer-in-docker-image-size-memory-and-performance-optimisation-58b0 · https://thebrowserlayer.com/posts/running-headless-browsers-inside-docker-containers

### The gap

We have the pure pose function (`rnPose(t)`, scrub-seekable, transitions frozen for capture) — the hardest part, and the part Remotion/HyperFrames are built around. We then *verify* it primarily through the one path those tools refuse to use for output: realtime playback with a sampler, an audio clock, and a jitter tolerance. And our browser launch is artisanal per job (private port: yes; everything else: rediscovered per record), with a known SIGTRAP failure that has a standing note but no pinned launch recipe, no fallback, and no environment census (shm size, sandbox mode, binary path/version) printed on any gate face.

### Concrete change to our machine

1. **Split the gate into two named instruments and demote realtime.** (i) *Frame gate (authoritative):* deterministic stepping — launch with `--deterministic-mode --enable-begin-frame-control --run-all-compositor-stages-before-draw --deterministic-fetch` (or `--virtual-time-budget` for the CLI path), drive `rnPose(frame/fps)` per integer frame, capture via `HeadlessExperimental.beginFrame` at explicit `frameTimeTicks`; every beat window ≥1 frame is then *guaranteed* sampled — the 0.07–0.12 s miss class disappears by construction (at 30 fps a 0.07 s window is 2 frames, always landed on). (ii) *Playing pass (smoke only):* one realtime play retained as a human-plausibility check, explicitly non-gating for beat existence and audio advance.
2. **Audio handled as data, not as a clock race:** assert narration sync from the timing table + audio file duration/sample count (see §c), and in the frame gate pose the audio cursor by seek (`currentTime = t; paused`) rather than measuring realtime advance. A5's environmental failure class is deleted, not tolerated.
3. **One pinned launch recipe in the job file, printed on every gate face:** binary + version, flags (`--no-sandbox --disable-dev-shm-usage` or a measured shm size, private port, fresh profile dir under the job tree, `--disable-gpu` / software-GL choice stated), and an environment census line (uptime, `/dev/shm` size, `/tmp` free — TOOLS.md already teaches `df -h /tmp` first). If the pinned recipe traps (rc 133), the *recipe's* fallback fires automatically: chrome-headless-shell ↔ full Chrome headless new, then a non-Chrome screenshot fallback for stills only — never a silent pause (the “problem is the work item” rule).

## (b) Chroma / magenta keying residue on placed assets — premultiplied-alpha pipelines

### OUR measured state

1. **Native-clean ≠ placed-clean; the residue is born in the resample.** Standing lesson, tab2-work AGENTS.md (city-skin2, 2026-11-07): “a keyed skin can census CLEAN at native resolution (0.0000% residue) and fail leg 2 after placement (0.0218%) — the residue is born in the placement resample: all failing px sat ≤2 px of the silhouette edge, ground colour blending in.”
2. **The cure was found locally — and it is manual.** Same lesson: “The cure is a MANUAL float premultiplied-alpha resize (premultiply → per-channel LANCZOS → un-premultiply), which cut residue 314 → 99 px (placed 0.0069%, PASS).” Full verification in `growth-skins-record-2026-11-07.md` §Attempt-3: a synthetic control (red bar on magenta) proved the manual path holds pure subject colour (200,30,30) where straight LANCZOS bleeds (223,33,33); ground pixels at α=0 “contribute exactly 0 to every resampled colour” under premultiplication.
3. **PIL `RGBa` does NOT premultiply on this build — measured, twice.** Growth record: “a first pass through PIL's `RGBa` round-trip reproduced attempt 2's file pixel-for-pixel (314 px, identical census)… so the PIL round-trip did not in fact premultiply.” v155 build record (§7) repeats it as standing method: “manual float premultiplied-alpha LANCZOS … (the recorded city-skin2 attempt-3 cure — PIL `RGBa` does not premultiply on this build).” Yet every new keying script still has to *remember* this; nothing in the pipeline enforces it.
4. **The key itself fights three generator-painted ground signatures**, all measured and codified in tab2-work AGENTS.md: ground-shadow strip (generators darken the magenta ground itself, distance ≈52–66, inside the key ramp — up to ~52k px retained per generation), DARK-PLUM pooled shadow (keys OPAQUE, escapes the first strip), PALE-GLOW edge glow — plus per-file calibrated masks (union of two predicates + border-median distance <42) in every keying script (`claim-round/key_wave3.py`, `key_wave3b.py`, `key_skin4.py`). The wave-3 record (`skins-keying-record-2026-11-07.md`) shows the cost: pass 1 → magenta-pocket cure pass → per-file re-calibration for tags-skin2, where the PALE-GLOW strip ate three white cards (opaque 3.23%, *passing every presence-based census* — caught by viewing, not numbers).
5. **The rim class hid from both legs.** `build-record-v70-keyrim-y1.md`: a saturated purple rim (mean RGB ≈ (132,64,154), ~2 px deep, ~76% at full alpha; digit-3: 7,593 core-rim px) “is the magenta key's own colour welded into the silhouette's outer band… at the one place neither of V's legs looks” — the family census filed it under the subject's own family and the edge-tint test only caught the outermost fringe (514 px). A whole new instrument (`census_y1.py`: core ∧ distance-to-non-core ≤2 ∧ purple-family) had to be invented to see it. The same record also shows census fragility: the predecessor's set-wide rim table “does not reproduce” (sign counted 5,264 vs 797 purple px in the file *in total*) — measurements were right, instruments were ad hoc.
6. **Residual instability is still open.** FREEZE-v154 re-grade face (2026-11-07): “placed-file fringe census instability (23/106 semi-band residue; invisible at display size; **open measurement problem**).”

### The field's cure

- **Premultiply-before-resample is textbook, with named library support.** libvips' shrinking HOWTO is a three-step recipe: “If the image has an alpha channel, you need to premultiply before shrinking… For the final resize, use `vips_reduce()` (lanczos3)… If you have an alpha, now's the time to call `vips_unpremultiply()`.” `vips_premultiply()` is a first-class float operation, not a hand-rolled numpy pass. — https://github.com/libvips/libvips/wiki/HOWTO----Image-shrinking · https://www.libvips.org/API/current/method.Image.premultiply.html
- **Pillow's own definition confirms what `RGBa` *should* mean** — “Premultiplied alpha is where the values for each other channel have been multiplied by the alpha. For example, an RGBA pixel of (10, 20, 30, 127) would convert to an RGBa pixel of (5, 10, 15, 127)” — and Pillow calls `RGBa`/`La` support “limited”. Our measurement (round-trip ≡ straight resize) is consistent with resize not honouring the premultiplied representation on this build: the mode exists, the resampler path is the trap. — https://pillow.readthedocs.io/en/stable/handbook/concepts.html
- **FFmpeg is converging on explicit alpha-mode tagging because untagged alpha is the bug class.** The 2025 alpha-mode series adds `AVFrame.alpha_mode`, a `premultiply` / `premultiply_dynamic` filter, and scale handling with the reasoning stated in-tree: “prefer premul alpha when scaling, because scaling in straight alpha will leak garbage pixels”; zscale gained “support for scaling premultiplied alpha (which reduces artefacts near the image borders)”. PNG is straight alpha by spec; OpenEXR is premultiplied by spec — the pipeline must *declare* which it holds at each step. — https://code.ffmpeg.org/legrosbuffle/FFmpeg/commits/branch/master/libavfilter · https://patchwork.ffmpeg.org/project/ffmpeg/patch/20250723135626.1390296-15-ffmpeg@haasn.xyz/
- **Key at native, despill, and composite in premultiplied space** is the VFX norm the above encodes: chroma keying produces a matte; all filtering/resampling of the foreground happens premultiplied; un-premultiply only at the delivery boundary. Independent HTML→video pipelines rediscover the same rule empirically — e.g. an h2v pipeline's hard rule: “filter order in ffmpegStitch is premultiply *then* scale (scale alpha in premultiplied space to avoid edge halos)”. — https://github.com/drewharvey/html-to-video/blob/HEAD/CLAUDE.md

### The gap

Our *knowledge* is at field level — we measured the RGBa trap, built the correct manual cure, and proved it with a synthetic control (better practice than most write-ups). The gap is purely structural: the cure lives in **prose lessons and per-script re-implementation**, so (i) any new script that resizes a straight-alpha file silently reintroduces the bleed, (ii) censuses run at native resolution certify a state the audience never sees, and (iii) each new ground signature (shadow/plum/glow — three so far) is a new strip invented per batch instead of one keying contract. The field does not have a better *key* for generator-painted magenta grounds than ours — see the report-back note — but it never lets a non-premultiplied resize exist in the pipeline at all.

### Concrete change to our machine

1. **One alpha library function, no other resize path:** `premul_resize(src, size)` implemented once (float premultiply → LANCZOS per channel → un-premultiply, α=0 colour zeroed), with the red-bar-on-magenta synthetic control as its unit test run on every use-day; keying/placement scripts import it, and a grep gate fails any build script containing a bare `.resize(` / `thumbnail(` on an RGBA asset. Preferably re-implement it on libvips (`premultiply → reduce → unpremultiply`, float end-to-end) so the operation is a maintained library's, not ours.
2. **Census only the placed file, at placed size, on the served stage background** — native-resolution leg-2 passes become advisory. The placed census adopts the Y1 rim instrument permanently (core-rim ≤2 px purple-family count = the headline number), which also closes the FREEZE's “fringe census instability” item by giving the semi-band a fixed definition instead of per-round probes.
3. **Declare alpha mode per file in the asset registry** (straight on disk per PNG/WebP convention; premultiplied only transiently inside the resize), mirroring FFmpeg's alpha_mode tagging — a file whose mode is undeclared cannot be placed.

## (c) Timing derived from word timestamps (faster-whisper `words.json`) — drift / rounding risks

### OUR measured state

1. **The whole visual layer is locked to one word table.** Alignment synthesis / Tab 2 law: “Timing allocates panels: every visual element's screen time derives from the word timings… an element allotted a fraction of a second is a tile or marker passing through a persisting scene, never a scene of its own.” The decision table (word ladder) carries each element's span from word timings; `rnPose(t)` poses are keyed to those seconds (segment-fix diagnosis prints the ladder verbatim, e.g. “300” 9.28–9.70, “times” 9.70–10.30, sentence pause 1.45 s inside “count” 6.22–7.673).
2. **The source is faster-whisper's native word timestamps** — i.e. Whisper cross-attention DTW timestamps, quantized and rounded in the page: U1W entries in the shipped HTML are stored to **millisecond-rounded decimals with visible float artefacts in the record chain** and word *ends* are not stored at all — “a word's end is the next word's start” (`segment-fix/diagnosis.md` §1). Pauses are therefore folded into the preceding word's span by construction; any rounding at ingest propagates into every pose boundary derived from it.
3. **Sub-100 ms decisions are being made on this table.** Pose boundaries at 0.005–0.01 s granularity were probed in fix10 (61 poses requested 0.40–0.70 step 0.005, “effective step 0.01 after the scrub element's own step sanitisation”) and event windows of 0.07–0.12 s are treated as real beats (§a). The table's own error bars are never printed next to it — no record states the aligner's expected boundary error, a confidence per word, or a Δ check of the table against the actual narration audio after the clone master changed. Tab 1's clone-timing tile exists in the page (the v154 served gate even fails trying to tap it), but no leg-C-visible record locks table↔audio with a measured offset.
4. **Known local symptom class:** the 4.17 s static span (segment-fix diagnosis §2) was a *staging* decision, not a timing error — the ladder was accurate enough to prove the tableau sat unchanged from 4.36→8.53 s while ten words passed. The timing risk in our machine is not gross drift on a 32 s unit; it is **silent small error at exactly the boundaries where sub-second visual beats are decided**, plus re-derivation risk whenever narration is re-generated (new clone take → old `words.json` → every span shifts by an unmeasured amount).

### The field's cure

- **Whisper's native word timestamps are the weak instrument; forced alignment is the production one.** WhisperX (Bain et al., INTERSPEECH 2023): Whisper word timestamps come from cross-attention DTW and are “prone to inaccuracies”; WhisperX adds VAD cut-&-merge (≈30 s chunks, preventing long-form drift accumulation) + **wav2vec2 phoneme forced alignment**. Measured at 200 ms tolerance: Switchboard precision **93.2% (WhisperX) vs 85.4% (Whisper)**; AMI precision 84.1% vs 78.9%, recall 60.3% vs 52.1%. The wav2vec2 CTC frame stride is **20 ms**, so aligned boundaries live on a 20 ms grid with TIMIT mean boundary error ~34 ms / median ~23.5 ms in independent scoring. — https://qwern.net/doc/www/arxiv.org/f064b57e6c5ea8f2da64ee63fd17a13dccd4caa0.pdf · https://github.com/attevon-llc/opentranscribe/blob/HEAD/docs/WHISPER_TIMESTAMP_DRIFT_RESEARCH.md
- **Montreal Forced Aligner (MFA) is the accuracy leader for a *known* transcript** — which is exactly our case (the transcript is authored, not discovered). MFA (Kaldi GMM-HMM + pronunciation dictionary) works on **10 ms frames**; `--fine_tune` re-aligns boundary neighbourhoods at **1 ms** step (with the honest caveat that 25 ms feature windows smear the true bound). Rousso et al. 2024, TIMIT: boundaries within 25 ms — **MFA 72.8% vs WhisperX 52.7% vs MMS 43.5%**; within 50 ms — 89.4% / 82.4% / 75.7%. MFA also *exports its own doubt*: `alignment_analysis.csv` with per-utterance log-likelihood, phone-duration deviation, SNR — flags for misalignments instead of silent numbers. — https://montreal-forced-aligner.readthedocs.io/en/stable/user_guide/implementations/fine_tune.html · https://montreal-forced-aligner.readthedocs.io/en/latest/user_guide/implementations/alignment_analysis.html · https://www.speechdata.ai/blog/forced-alignment-speech-data
- **aeneas is the cautionary branch, not a candidate:** DTW of MFCCs against *synthesized* speech (Sakoe-Chiba band DTW) — serviceable for audiobook phrase sync, but word-level granularity is its weak level, and the project is unmaintained (last release 1.7.3, 2017). — https://www.readbeyond.it/aeneas/docs/runtimeconfiguration.html
- **Known forced-alignment failure modes to design around** (WhisperX literature): dictionary/character limits — digits and out-of-vocabulary tokens get **no true alignment** and are interpolated from neighbours (directly relevant: our most-timed words are numerals — “3.2”, “300”); wav2vec2 is less noise-robust than Whisper; MFA needs G2P/pronunciation entries for OOV words or it emits `<unk>`. Any pipeline must print which words were *aligned* vs *interpolated*.
- **Locking practice:** productions treat the aligned table as a *derived artifact of a specific audio file*: regenerate alignment whenever the audio changes, store start **and** end per word (pauses as explicit silence intervals from VAD), keep the aligner's confidence/analysis beside the table, and verify Δ by re-probing a sample of boundaries against the waveform (energy onset) — the table is versioned with the audio's hash, never copied across takes.

### The gap

We use the weakest of the three timestamp sources (native faster-whisper DTW words) at the highest precision demand (5–10 ms pose probing, sub-100 ms beats), with ends inferred, pauses folded into words, no per-word confidence, no aligned-vs-interpolated flag on the numeral words that carry the film's biggest beats, and no recorded Δ verification against the final clone audio. The field's gap-closer is cheap for us precisely because our transcript is *known text read by a known voice*: forced alignment is the textbook fit.

### Concrete change to our machine

1. **Replace the timing source:** run MFA (10 ms grid, `--fine_tune` on boundary-critical words) — or WhisperX if MFA's dictionary fights the clone voice — over the *final* narration master + the authored transcript; ingest **that** as the word ladder. Keep faster-whisper words only as a cross-check; print the median/max |Δ| between the two tables on the build face (expected: tens of ms; any word >100 ms is a named exception).
2. **Change the table's shape:** store `[start, end, word, aligned|interpolated, confidence]` per word, pauses as first-class silence rows; hash the audio file into the table header — a build whose audio hash ≠ table hash cannot render (the re-take drift class becomes impossible, not checked-for).
3. **Quantize honestly:** pose boundaries snap to the frame grid (frame/fps) at build time from the aligned table, and the table prints its own error budget (aligner + grid) — decisions finer than the budget (e.g. 5 ms probes) are flagged as under-resolution instead of being measured as if real.

## (d) Served-vs-tested byte drift (pushed page ≠ tested page; CDN lag)

### OUR measured state

1. **The lag is measured in tens of minutes, not the “1–10 minutes” folklore.** Asset-parity verification note (2026-11-06): after commit `c8ed003e`, the served `shard-piece-01-clean-v1.webp` was polled cache-busted every ~2 min for **30 minutes (15 polls, 23:04→23:32 UTC) and never flipped** — served sha stayed `9d4de628…` (old generation) vs current `2db75218…`. Result printed plainly: “NOT VERIFIED — the served assets had NOT flipped within the 30-minute bound.”
2. **The watch discipline exists and is good — but it is a watch, not a gate.** fix6/fix7/fix8 records: byte-level polls of both served paths every ~2 min, “raw bytes fetched to a file with a cache-busting query parameter on every poll; the file itself hashed with `sha256sum` (no shell substitution / pipe hashing)” (fix7: target prefix `ff7636a2` v150 vs stale `3f9b4cc3` v149). fix10/fix-player lines keep local, serve, and pushed trees as three separately-sha'd states (v154 page `34eb6cc2…` staged-not-pushed; serve tree verified still at v153 `6d214d52…`; “Not claimed LIVE”). FREEZE-v154 re-grade: “HEAD of both index paths re-fetched == v155” before presentation. The *vocabulary* (staged / served / live) is disciplined.
3. **But the dual-path duplication invites drift:** the same page is pushed to **two repo paths** (`quadrillion/index.html` and `dashboard/quadrillion/index.html`) in separate commits (v155: `4df17b1e` + `669c076f`), doubling the surface where one path can flip and the other not; and un-versioned asset URLs mean a flipped HTML can still compose with stale assets — exactly the parity failure in (1), where the *page* had moved on and an *asset* had not.
4. **Gate runs against “served” inherit the ambiguity:** served gate outputs exist beside local ones (`fix-player-gate-v154-served-output.json`, `fix8-gate-served-v152.json`, `fix10-served-run/`) — good practice — but a served run during a partial flip tests a chimera (new HTML + old assets) and its failures (e.g. served A5/tab1 fails) cannot be attributed to build vs CDN without the per-file sha manifest the parity note had to improvise.

### The field's cure

- **GitHub Pages' cache contract is fixed and short — the long tail is propagation + un-versioned assets, so the cure is addressing, not waiting.** Pages serves HTML with `cache-control: max-age=600`; the standard mitigations are (i) **content-hashed / versioned asset URLs** — “injecting a unique, content-derived hash into every build… every asset URL carries `?v={hash}`, so a CDN that keys on URL sees something new to fetch… an unchanged rebuild keeps the same hash” — and (ii) a build-id meta for verification. Pages offers no cache-purge or header control, which is precisely why URL-keying is the lever. — https://freestruct.creadev.org/guides/cache-busting-faq/ · https://dropto.run/blog/old-version-after-deploy
- **Verify at the commit SHA first, then at the live URL** (deployed-artifact verification practice): the SHA-addressed raw URL is the source of truth for “was it committed”; the branch URL and the Pages URL are CDN views that “can serve stale bytes for minutes while the SHA URL is already correct”. A push is not a deploy; the deploy is only the moment served sha == target sha on *every* file in the manifest. — https://github.com/ahrazzle/team6-kit/blob/HEAD/templates/skills/software-development/verify-deployed-artifacts/SKILL.md
- **Manifest-first verification:** a `MANIFEST.sha256` regenerated after any post-manifest edit, checked with `sha256sum -c`; live probes batch-fetched with cache-busters and hash-compared file-by-file (“download served asset, hash vs workspace copy — deployed bytes == reviewed bytes”); stale-reference sweeps for retired asset paths, with cache-busting required in the same pass when stale bytes have bitten before. — https://github.com/ahrazzle/team6-kit/blob/HEAD/templates/skills/software-development/web-build-verification/SKILL.md

### The gap

Our polling/hash method already matches the field's verification workflow — this is our strongest class. The gap is addressing: assets are referenced by **stable names** (`shard-piece-01-clean-v1.webp` — the `-v1` is a human version, not a content hash, and a regenerated file can keep the name), the page lives at **two paths**, and “live” is asserted per-page rather than per-manifest. So flips are partial by design and every push pays a 2-minute-interval human/agent watch. The field pays none of that: a content-hashed URL cannot serve the wrong generation, and a manifest check is one command, not a 30-minute poll.

### Concrete change to our machine

1. **Content-address the assets at push time:** the push builder rewrites asset refs to `name.<sha8>.webp` (or `?v=<sha8>` where filenames must stay stable for the registry) — a stale edge can then only serve a *complete old version*, never a mixed one; the parity-failure mode (new page + old shard) is eliminated by construction.
2. **One manifest, one verdict:** every push emits `MANIFEST.sha256` for page + all referenced assets at both repo paths; the “LIVE” claim requires a single automated check — fetch every manifest entry cache-busted, hash, compare — printing `files total / flipped / stale-named`. Polling remains only as the retry loop *inside* that check (bounded, e.g. 45 min, then the face prints STALE with the named files — the problem-as-work-item rule), never as a human watch.
3. **Collapse to one canonical path** (the second path becomes a redirect or a byte-identical mirror verified by the same manifest), halving the flip surface.

## (e) Provenance / cleanliness failures — assets cut from composed pictures, baked backgrounds / shadows

### OUR measured state

1. **The original sin is documented in our own cures.** Stage-1 Unit 1 assets were *extracted from composed album frames* (`album-assets/u1p1-f*.webp` etc.) by region-growing / polygon tracing / flood+texture-gate (`tab2-work/AGENTS.md`, Unit 1 asset production lesson) — with measured failure modes per method: region-growing “hollowed A11's burst spikes and ate A22's pile top”; global threshold failed on vignetted grounds; A21's polygon extraction **clipped the banner's bottom strip (~24–44 px)**, cutting “TEXT EVER” at mid-letter (`a21-cure-record.md`). A22's “notch” turned out to be a detached fragment of **lit wall + cast shadow and a piece of curtain** carried inside the asset (626 px + 418 px + nine specks, all identified by registration against the frame and dropped).
2. **The two-leg bar was the corrective — and it is genuinely strong.** Standing law (alignment synthesis + every recent record): **Leg 1 provenance** — how the asset was made: generated independently from its own written description, extraction/cutting from a composed picture banned as an asset-making method; the description is written *first* and is the contract (`growth-skins-record-2026-11-07.md`: “description written FIRST… → generate independently from that description on a solid magenta ground → key…”). **Leg 2 cleanliness** — the file itself: object only, no baked background/shadow/foreign material, proved by halo (=0 beyond 6 px), stray (=0 beyond 10 px), magenta-interior, border, and semi-veil censuses on the *saved file* (`skins-keying-record-2026-11-07.md`). Contact shadows are now *drawn by the scene*, never baked (v155 build record, A3: new `#rnShadowSvg`).
3. **But the bar's limits are also measured.** (i) It is enforced **per batch, by hand-built probes** — `probe_twoleg_v70h.py` is “the standing strict instrument” only because a tolerance amendment was tried and REJECTED at programme level after a guard re-run flipped a must-fail file (A13 debris 690→31) — the record notes “16 of Workstream I's 23 characterization-regime passes do not read as raw passes under the strict bar… ‘passes the two-leg bar’ is ambiguous until the programme names which bar it means” (`build-record-v70-tolerance-tol.md` via AGENTS.md). (ii) Presence-based censuses passed a file that had lost its subject (tags-skin2's eaten cards, §b) — cleanliness ≠ completeness. (iii) Provenance evidence is **prose + sidecar JSONs in-folder** (media-generation-*.json, sha prints in records): strong inside our file system, invisible outside it — nothing binds the description/prompt/sha *into* the asset file, so a file that leaves the folder leaves its provenance behind. (iv) The generation side still paints the dirt the key must strip (§b ground signatures; generators “paint soft shadow/VIGNETTE onto the magenta ground itself”), so cleanliness is achieved by cure, not by generation contract compliance.

### The field's cure

- **C2PA / Content Credentials — provenance as a signed, hash-bound manifest *in* the file.** The C2PA spec: a Content Credential is “a cryptographically bound structure that records an asset's provenance” — assertions about origin, modifications, and AI authorship, including **ingredient** assertions for composed assets, wrapped in a claim signed by the producing software; a hard binding (cryptographic hash of the content) ties the manifest to the exact bytes, so any post-signing change breaks validation. The spec is explicit about its limit: it proves the assertions are “well-formed and free from tampering” and attributable to a signer — *not* that they are true. — https://spec.c2pa.org/specifications/specifications/2.2/explainer/Explainer.html · https://spec.c2pa.org/specifications/specifications/1.0/specs/C2PA_Specification.html
- **The registry pattern underneath it** (what C2PA standardises, and what ML/data pipelines do with model/dataset cards and content-addressed stores): every asset carries (1) a content hash as its identity, (2) a machine-readable record of *how it was made* (prompt/description, model, settings, source ingredients by hash), (3) an append-only transformation chain (each derived file names its parent hash + the transform), so “cut from a composed picture” is not a judgment call — the ingredient list either names a composed frame or it doesn't.
- **Cleanliness has no external standard** — and this matters for the report-back: no C2PA assertion, imaging library, or VFX spec defines “object only, no baked shadow” as a portable check. The field's equivalent is pipeline-side: generate/plate elements on flat grounds, keep shadows as separate elements/passes (the multi-pass compositing norm our scene-drawn `#rnShadowSvg` now follows), and QC the element file before comp. Our halo/stray/rim censuses are *more* rigorous than common practice here.

### The gap

On cleanliness we are at or ahead of the field (see report-back). On provenance our *rule* matches the field's intent (description-first, no extraction, ingredient honesty) but our *mechanism* is weaker in three ways: it is prose-bound rather than hash-bound (a file can be copied out of its record), it is ambiguous at programme level (two coexisting bars — strict vs characterization — with passes under one reading as fails under the other), and it has no completeness leg (a clean-but-hollow asset passes). C2PA itself would only fix the first of these, and only with signing infrastructure disproportionate to a one-operator studio — the transferable part is its *data model*, not its PKI.

### Concrete change to our machine

1. **Adopt the C2PA data model without the PKI:** one machine-readable `provenance.json` per asset in the registry, generated at creation, containing: description/prompt verbatim, generator + generation-record id, raw sha256, keyed sha256, parent/ingredient hashes (for any derived file), the transform script name+version, and the two-leg census results. The asset's registry entry *is* this file's hash; a build that references an asset with no provenance record, or whose current sha ≠ recorded sha, fails the gate. (If external publication ever needs it, this maps 1:1 onto C2PA `c2pa.actions` + `c2pa.ingredient` assertions and can be signed then.)
2. **Name ONE bar:** fold the tolerance question to a programme decision recorded once (strict `probe_twoleg_v70h` numbers as the gate; characterization notes as advisory text, never as a pass), and re-run the guard set whenever the bar's code changes — the TOL record's own rule.
3. **Add Leg 0 — completeness:** subject-presence measured against the generation's own description (opaque-mass band + component inventory + the keyer's viewed contact sheet, as wave-3 did by hand) so “clean but eaten” fails mechanically, not only when someone views it.
4. **Push the contract upstream:** generation prompts already demand “NO drop shadow, NO cast or contact shadow, NO ground plane” (growth-skins record) — make the three measured ground signatures (shadow/plum/glow px counts on the *raw*) a generation-acceptance census, so a dirty raw is rejected/regenerated before keying labour is spent on it.
