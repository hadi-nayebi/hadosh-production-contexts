## Findings
- **A learning map is a backward-design artifact, not a summary.** Written after the text, in the text's order, it describes; written before transcript lock — learnings → evidence → lines/scenes — it prescribes. Quadrillion's re-derived map works because it was re-derived from the corrected text with a citation-change table; nothing in the standing model required that.
- **Density is per-movement, not per-piece.** §5.9 asks only for a total runtime + density justification. The editorial pacing debit is local: one movement at ~33% of words with the piece's highest new-concept load and no internal re-engagement. A per-movement table (words · seconds · new learnings · new named concepts) makes that flag computable before build.
- **A gap must be primed.** The skill's fit test asks for "a specific primable question" but no row checks the prime was actually supplied, or names where the gap closes / transfers to. Loewenstein supplies the failure mode: unprimed = no curiosity; unclosed-and-untransferred = clickbait (already the skill's payoff-honesty rule, now checkable per loop).
- **Currency is bidirectional.** Map→text (a learning citing a dropped line) and text→map (a line delivering an unstated learning) both fail. The check runs against the operative text, never a draft, and a restored/corrected transcript voids the map — re-derive, do not patch, with the citation-change table as proof (tab0-work AGENTS.md lesson, 2026-10-30 — lifted into the standing model by this session).
