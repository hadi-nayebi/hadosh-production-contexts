## §1 Geometry pricing (filed before building, from the standing stage geometry)

Stage: 16:9 box. Reference stage sizes: 360 px wide → height 202.5 px;
390 px wide → height 219.375 px.

Designer-named minimum readable font floor for listing text: **11 px**
(absolute CSS px at the rendered stage size; listing, prompt, caption and
label text are all held at or above this floor).

Layout budget (fractions of stage height H):
- Prompt zone: listing window starts at 14% of H.
- Caption zone: 16% of H reserved at the bottom (caption text plus its
  offset and clearance); the listing window ends at 84% of H.
- Listing window height: 70% of H → 141.75 px at 360 width;
  153.56 px at 390 width.

Derived listing typography:
- Listing font size = 0.0543 × H, floored at 11 px → 11.00 px at 360 width;
  11.91 px at 390 width.
- Line-height ratio 1.3 → row height 14.30 px at 360 width;
  15.49 px at 390 width.

Row-count requirement priced against the window:
- 13 rows × row height = 185.90 px at 360 width vs 141.75 px available
  (shortfall 44.15 px); 201.31 px at 390 width vs 153.56 px available
  (shortfall 47.75 px). Holding 13 rows would require the listing window
  alone to occupy 91.8% of stage height, leaving no room for the prompt
  zone and the reserved caption zone inside the same stage.
- Rows that fit fully inside the window at or above the floor:
  floor(141.75 / 14.30) = 9 at 360 width; floor(153.56 / 15.49) = 9 at
  390 width.
- Disposition: the layout derives its visible row count from the window
  height and the row height at run time, so every row inside the window
  is fully within the window bounds at the floor size. The 13-row figure
  is not claimed by this construction; its status is filed in scores.md.

Column pricing:
- Listing column: left offset 3.5% of stage width, width 62.5% of stage
  width → 225.00 px at 360 width; 243.75 px at 390 width.
- Numeral column: width 31% of stage width → 111.60 px at 360 width;
  120.90 px at 390 width. Numeral font size = H / 3 → 67.50 px at
  360 width; 73.13 px at 390 width. Two-digit width at a 0.72 em digit
  advance ≈ 97.19 px at 360 width; 105.29 px at 390 width — inside the
  numeral column at both widths.
- Longest listing lines: 36 characters. At a 0.6 em monospace advance,
  plus one check glyph (0.6 em) and the row gap (0.45 em), a 36-character
  line needs 22.65 em of listing font: 249.15 px at the 360-width font
  size vs the 225.00 px column; 269.81 px at the 390-width font size vs
  the 243.75 px column. Fitting those lines inside the column would
  require a listing font of 9.93 px at 360 width and 10.76 px at
  390 width — below the 11 px floor at both widths. The need-to-column
  ratio (1.107) is constant across stage sizes in this layout.
- Disposition: horizontal fitting of the 36-character lines at or above
  the floor is not claimed by this construction; its status is filed in
  scores.md. All shorter lines fit inside the column at both widths.

Interactions recorded:
- Caption reservation vs listing height: the reserved 16% caption zone
  is what bounds the listing window to 70% of H; removing the
  reservation would still leave 13 rows short (13 rows need 91.8% of H
  against an 86% ceiling with prompt zone only).
- Numeral allocation vs column width: widening the listing column past
  66.7% of stage width would leave the numeral column narrower than the
  two-digit numeral width priced above.
- Line fitting vs font floor: both the row-count requirement and the
  longest-line requirement price below the floor; the floor is held in
  both cases.

## §2 Construction facts

- Single self-contained HTML file; every visible element is generated by
  code from the CONFIG block at the top of the script. No external assets
  of any kind; the listing lines, the command text and the caption text
  are CONFIG data rendered as text.
- Schedule anchors are CONFIG data: (0 ms, 0) · (3000 ms, 20) ·
  (6000 ms, 37) · (7000 ms, 39) for the 39-line default set, with a
  7000 ms caption point and an 8000 ms total duration. Line reveal times
  interpolate evenly between anchors; the numeral always equals the
  number of lines whose reveal time has passed, computed by the same
  function that drives the rows.
- The directory command is present in full from t = 0; no frame of the
  render path writes to the command text.
- Numeral scale: CONFIG pulseScale is 1.0, and the scale applied to the
  numeral is a pure function of timeline time (elapsed ms, the schedule
  anchors, pulseScale, pulseMs). At the default the function returns
  exactly 1 at every sampled time.
- Caption construction: the caption element is assembled from text
  nodes plus one generated span carrying the accent character
  (CONFIG captionAccentChar, default "0") in the accent color at
  1.25 em. No HTML-parsing assignment exists anywhere in the file, on
  any code path, including all override paths.
- Schedule normalization: the effective schedule is derived from the
  line count. A configured anchor table that validates against the
  current line count (first anchor 0/0, strictly increasing times and
  counts, integer counts within bounds, terminal count equal to the
  line count) is used as given; any other table is replaced by a
  count-normalized derivation that scales the anchor counts by
  (line count / default anchor total), keeps anchor times, drops
  non-increasing counts, and appends the terminal count at the final
  anchor time when rounding leaves it short. Every line index has a
  finite reveal time not later than the final anchor time, for any
  line count.
- Validation: checkpoint tables, color overrides (hex form only), the
  speed override (finite, in (0, 10]) and the checkpoint-time override
  (strictly between its neighbouring anchor times) are validated at
  load; a rejected value leaves the default in place and appends a
  named entry to the warnings list exposed on the page interface
  (window.T02.warnings). An empty caption override is honored (the
  parameter is present, so it applies). The line-count value is always
  the length of the current lines array.
- The count function iterates at most the schedule's terminal count of
  lines; no fixed numeric ceiling exists in the source.
- Clock: one animation-frame loop exists at a time. A single guarded
  starter begins the loop only when no loop is active; seeks render
  their target time directly and reuse the starter; the loop counter
  exposed on the page interface (window.T02.debug.loopStarts) counts
  loop starts. Playback state at any time t is a pure function of t
  through the schedule, the scale function and the layout derivation.
- Playback controls render in a bar below the stage element, outside
  the stage's box; the comparison page drives the same play / pause /
  restart / seek interface (window.T02 + postMessage) it used before.
  Button labels, fonts, colors, borders, padding and sizing are CONFIG
  values (controls block); type stacks (fonts block), layout
  percentages (layout block) and type ratios (type block) are CONFIG
  values.
- Layout derivation (a pure function of stage size and CONFIG): font
  sizes scale with stage height and are floored at the 11 px minimum;
  the visible row count is the smaller of CONFIG visibleLines and the
  count of full rows that fit the listing window; the numeral font
  size is one third of stage height (CONFIG numeralSizeRatio 0.3333).
