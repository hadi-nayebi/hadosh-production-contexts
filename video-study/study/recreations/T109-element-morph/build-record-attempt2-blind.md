## Construction

One self-contained HTML file; all values in a single CONFIG object at the top of the script. DOM primitives (a search bar with a title, three cards, a selection outline, a countdown line, three triangles) are composed from CONFIG geometry; no external assets, no specimen media, no traced contours.

Behaviour dispatch: a behaviours table keyed by the CONFIG correspondence entries' mode values (deform-to-cluster · collapse-to-point · collapse-down · color-interpolate). Each render step iterates the correspondence entries, resolves each entry's source element and destination (a triangle-cluster target, a palette target, or none), and applies that entry's own stagger. Changing an entry's mode or destination in CONFIG redirects the rendered behaviour without code edits.

Trajectories: collapsing elements follow one piecewise trajectory per element covering a preparation interval (the final countdown step) and the morph interval: a CONFIG prep fraction of the collapse completes by morph onset, with the element's stagger applied proportionally in both pieces, and the collapse completes inside the first stage of the morph interval. Collapsing "down" elements derive their top edge from a centre trajectory (the centre travels by the CONFIG sink distance), so centres only move downward. The destination reveal is staged inside the morph interval by CONFIG fractions: a clearance stage (webpage elements reach their terminal state, no triangle visible), then a lone first triangle, then the remaining triangles join and the cluster completes at morph end. The top card deforms (position, size, radius, colour) to the cluster bounding box across the clearance stage and yields to the triangles. The field colour-interpolates to black on its own correspondence entry (its stagger is independent). The settle interval moves triangles alone (a decaying scale overshoot). The return phase evaluates the same forward trajectories at mirrored time over the full preparation+morph span, so the return retraces the forward path element by element.

Schedule (t=0 allocation): holdA 2400 · countdown 3 × 1000 · morph 2000 · settle 900 · holdB 2600 · return 600 · residual 2500 · cycle 14000 (CONFIG cycleMs; the phase sum is validated against it — an over-budget configuration is a named validation problem and the piece renders an invalid state instead of truncating; scene-kind values are likewise validated against a supported set).

Phases are explicit and non-overlapping; the countdown and the selection outline exist only inside the countdown interval (the outline only in its final step); no whole-scene opacity is interpolated anywhere — the only opacities are per-element collapse/yield terms.
