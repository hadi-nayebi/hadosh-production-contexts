## §2 Construction (neutral technique facts)
- One self-contained HTML file; all variables in a CONFIG object at the top of the script; URL overrides for titles/stamp/cardMs/accent/bg are parsed strictly (an unsigned-integer grammar for cardMs), applied to a candidate copy, deep-validated, and only then adopted — an invalid candidate is rejected atomically and recorded in an observable rejected list while the default configuration renders.
- Scheduling is a single absolute timeline computed from CONFIG: card starts every 2000ms across a 10000ms loop (5 cards), counter spans, and one stamp event per card whose data flag marks it merged. Displayed state is a pure function of loop phase; a frame that skips several checkpoints reconstructs exactly the state those checkpoints produce; pause stores the phase and resume shifts the time origin; loop rollover is phase modulo.
- Derived subordinate durations: the counter span is the configured counter duration capped by the card interval minus half the whip; the stamp offset is capped so the slam + derived hold + hide always complete before the next whip window opens, and the hold is the remainder of that budget. At the default interval: counter span 1400ms, stamp offset 1400ms (the slam lands at counter completion on merged cards), slam 130ms, hold 220ms, hide 100ms.
- Stamp rendering: scale and opacity come only from the phase function; the stamp element's CSS transition is pinned to none at setup and on every render, so no per-frame transition retargeting can occur.
- Approvals counter: three digit columns; each column is a doubled 0–9 strip translated vertically by a continuous roll position computed from the phase-driven approvals value (hundreds/tens/ones positions derive from the same value), so digits roll during the rise and settle exactly on the card's target at span end. No blur is applied to the counter.
- Card transitions: one envelope per swap (300ms), swap at the envelope midpoint, horizontal travel 130px, blur peaking at the midpoint, a horizontal streak scale plus a skew component, opacity 1 throughout.
- Checks panel: row states, status-pill text and tone are data in CONFIG; while a merged card's stamp is displayed, the pill shows the merged entry. Check-state colors, pill tones, and palette colors are applied via CSS custom properties at init.
- Arch: code-drawn pointillist pointed arch from a shape function exposed as a pure cell function; geometry constants (profile knee, half-width ramp, leg start/gap, band frequency/phase/threshold, dark-cell pattern multipliers and modulus) and the three glyph characters live in CONFIG; the leg opening spans 0.34 of the normalized half-width and the rows below the leg start are 43% of the arch height; glyph size is 6.4px on a 36×28 grid.
- Reviewer figures are DOM figures (head, arms, body, legs) built from CONFIG figure dimensions including stroke widths; counts per card are CONFIG data.
- Stamp placement (left/top percentages), border width, padding, background, and font stacks are CONFIG values applied at init. Type sizes are CONFIG values applied at init.
- Validation walks every nested shape: card entries (field types, approval ordering, merged flag type), check rows (arity, known state names, labels), pill entries and tone tables (hex pairs), reviewer counts (non-negative integers), arch ranges, and type/figure/stage positivity; validation is exception-guarded so malformed values produce rejection errors rather than throws.
