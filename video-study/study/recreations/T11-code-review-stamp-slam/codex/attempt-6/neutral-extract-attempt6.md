## Specimen observations and timeline mapping
Specimen observations (builders' filed evidence): the segment is a 10-second window of a GitHub-like pull-request screen. State-at-sample observations: at approximately 2.5 s the first card (#1111) is displayed with its green stamp held at full size; at approximately 6.5 s the #1115-equivalent card is displayed with no stamp; at approximately 7.5 s that card's stamp is displayed held (not mid-slam). Frame-difference scans at 4 fps and at 10 fps found the specimen's own event spacing non-uniform (large transition clusters near 1.2–2.1 s and 9.6–10.0 s; no regular 2-second boundary grid at 100 ms granularity). Extraction granularity: 10 fps (100 ms) for the latest scan; boundary localisation on a continuously animated segment carries roughly ±100–300 ms uncertainty per edge. A uniform 2000 ms cadence from the loop origin would put the second card on screen at 2.5 s, which contradicts the first sample; the recreation's card durations are therefore non-uniform, and its card data set is its own parameterized set. Mapping: the recreation schedules five cards across a 10000 ms loop with per-card durations [2800, 1400, 1800, 2000, 2000] ms; the fourth card starts at 6000 ms so the 6.5 s and 7.5 s samples fall inside it; the first card's stamp is held across 2500 ms; the fourth card's counter settles before its stamp first appears, and its stamp is held across 7500 ms.

## Construction facts
- One self-contained HTML file; all variables in a CONFIG object at the top of the script. The shipped configuration is validated first at startup; only a valid shipped configuration proceeds to URL-override parsing, and an invalid one records its named errors in an observable rejected list and halts construction without throwing. URL overrides for titles/stamp/cardMs/accent/bg are parsed against a candidate copy, deep-validated, and only then adopted — an invalid candidate is rejected atomically and recorded in the same observable rejected list while the default configuration renders. Empty, duplicate, excess, and unrecognised override parameters are each rejected with a named error in the same observable record. The override parser reads the base configuration through guarded access, so a malformed base group yields named validation errors rather than an exception. Validation also bounds approval counts to the counter's capacity: any approval value at or above digitBase raised to counterDigits is rejected, with the bound computed from the configuration's own digit base and digit count. A valid configuration starts playing on its own and loops.
- Scheduling is a single absolute timeline computed from CONFIG: five cards with per-card durations [2800, 1400, 1800, 2000, 2000] ms across a 10000 ms loop, counter spans, and one stamp event per card whose data flag marks it merged. Displayed state is a pure function of loop phase; a frame that skips several checkpoints reconstructs exactly the state those checkpoints produce; pause stores the phase and resume shifts the time origin; loop rollover is phase modulo.
- Derived subordinate durations: each card's counter span is the configured counter duration capped by the card duration minus the whip duration; on a merged card the span is further capped so the stamp's onset follows the counter's settle by a configured gap. Each merged card's stamp offset is the smaller of a configured fraction of its card duration and the latest offset that lets slam + hold + hide complete before the next whip window opens; the hold is the remainder of that budget and the hide completes at the whip window's opening edge. At the default durations: counter spans are [1400, 1100, 1400, 1270, 1400] ms; first merged card stamp spans 1918–2650 ms (held at the 2500 ms phase); second merged card stamp spans 7370–7850 ms (its counter settles at 7270 ms, slam completes at 7500 ms, held at the 7500 ms phase).
- Stamp rendering: scale and opacity come only from the phase function; the stamp element's CSS transition is pinned to none at setup and on every render.
- Approvals counter: three digit columns; every column's strip position is an unwrapped, monotonic function of the rising value within each card — as the count crosses a multiple of ten or a hundred, each column's strip continues into its duplicated repetitions instead of snapping back. Each column's strip length is derived from the shipped card set (the maximum absolute local index any card reaches in that column, plus the glyph at that index and one further glyph for fractional positions), and the same derivation is what validation checks. Each higher column eases across the final fraction of its own carry span. At every counter completion each column's displayed strip position is exactly its settled digit. No blur is applied to the counter. The ones column's peak travel rates per card are approximately 106, 109, 100, 220, and 0 digits per second.
- Card transitions: one 300 ms envelope per swap, including across the loop boundary (the final card whips into the first card's entrance); swap at the envelope midpoint, horizontal travel 130 px, blur peaking at the midpoint, a horizontal streak scale plus a skew component, opacity 1 throughout.
- Checks panel: row states, status-pill text and tone, check-state symbols, and interface labels are data in CONFIG; while a merged card's stamp is displayed, the pill shows the merged entry. Check-state colors, pill tones, and palette colors are applied via CSS custom properties at init.
- Arch: code-drawn pointillist arch from a shape function exposed as a pure cell function; geometry constants (profile knee, half-width base/top, crown exponent, opening apex height fraction, leg gap, band frequency/phase/threshold, dark-cell pattern multipliers and modulus) and the three glyph characters live in CONFIG. The opening is a pointed arch: its boundary is two arcs meeting at a centre apex that reaches 78% of the figure's height in the configuration (75% as measured on the grid), widening monotonically to the configured leg gap at the base; measured opening half-widths rise from 0 at the apex row to 0.333 of the half-frame at the base row, the opening area is 181 cells, the crown peakedness measure (one minus the upper-region half-width ratio) is 0.228, and glyph size is 6.4 px on a 36×28 grid.
- Reviewer figures are DOM figures (head, arms, body, legs) built from CONFIG figure dimensions including stroke widths; counts per card are CONFIG data.
- Stamp placement (left/top percentages), border width, padding, background, and font stacks are CONFIG values applied at init. Type sizes are CONFIG values applied at init.
- Validation enumerates every container the render path dereferences and rejects — without throwing — when any is absent or a required member is missing; counting dimensions and length-limit members validate as finite integers in named ranges; position and padding values validate as finite numbers without string or null coercion; arrays validate by explicit index so a sparse entry is rejected by its index; scalar ranges are checked for every numeric family (durations, digit base, whip scalars, stamp scalars and strings, arch fractions and pattern integers, type/stage/figure values); a rejected candidate leaves the default configuration and timeline completely unchanged.
