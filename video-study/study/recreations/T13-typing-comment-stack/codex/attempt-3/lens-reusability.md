Configuration covers most content, palette, layout, and timing, but production reuse still requires source changes or undocumented restrictions. Named overflow freezes and shared grapheme helpers are useful safeguards; the fitting and override contracts remain incomplete.

- **Geometry units are not faithfully supported.** `modelFor()` treats `parseFloat()` results as cqw or percentages regardless of the CSS unit. Changing a font token to `"20px"` renders 20px but models 20cqw. `entranceDy` likewise accepts a CSS string but reconstructs its animated value in cqw. Validation can therefore approve or reject a different geometry from the rendered one.
- **Replacement chrome is only partly validated.** Card headers are checked, but post author/handle/close rows, comments title/sort rows, footer labels/actions, stamp text, and avatar initials lack fitting checks. Post-body fitting contributes to height accounting without its uncertainty being checked. Long replacement chrome can overflow without a named failure.
- **Title fitting can silently accept clipping.** `fitLines()` adds highlight padding after choosing breaks, but validation never rejects `maxWidthPx > innerPx`. The caret’s width and margin are also omitted. Whitespace normalization changes grapheme positions without remapping the highlight range. These discrepancies undermine the claimed replacement-content contract.
- **Override handling is inconsistent.** `accent` and `cardBg` bypass validation and rejection reporting; interpolation assumes six-digit hex, so shorthand or invalid values produce incorrect colours. With seven or eight replacement titles, `charMs` updates existing beats before `normalizeBeats()` adds new beats at hard-coded 38ms, leaving later cards unaffected by the accepted override.
- **Some reusable decisions remain outside configuration.** Added-card entrance/rate defaults, the replacement prefix length of 15, caret duty cycle, several line heights/font weights, and the stage maximum width are hard-coded.
- **Timing edges lack configuration guards.** `landMs`, `caretBlinkMs`, and `finalHoldMs` lack finite/range validation. Configurable landing durations can exceed the interval before the next card begins; there is no named validation preserving the required completed landing before subsequent typing.
- **Unicode support is qualified.** Native segmentation consistently supports typing and highlight lookup. The fallback explicitly excludes some extended grapheme rules, so arbitrary Unicode remains unsupported there.

Card-count overflow is bounded and reported honestly. However, the record’s passing checks do not establish safe arbitrary reskinning or repopulation, particularly without rendered fitting evidence.
