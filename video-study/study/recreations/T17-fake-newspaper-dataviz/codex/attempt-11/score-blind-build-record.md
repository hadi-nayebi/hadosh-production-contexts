# Build record (score-blind) — T17 fake-newspaper dataviz, current build

Single self-contained HTML file; all subject matter, timing, geometry, and presentation values live in one CONFIG object (338 leaf values, including per-figure records). Six figures in fixed windows across 22.5 s. The piece self-starts in top-level mode and exposes a public interface: render, play/pause/restart, setTime, validate, fitReport, and rebuild(candidate) which remounts a changed configuration atomically.

## Public swap construction
- The rebuild path clones the candidate, validates it, evaluates fit, builds the replacement detached, then publishes. A complete snapshot of the live scene is taken before any publication write: children, configuration, playback state, and the full presentation state (stage class, stage height, inline background and colour, all 44 stage variables, the document width variable, body background, clock colour). Publication begins only after the snapshot verifies complete; a snapshot failure returns a failure result with zero publication writes.
- On any publication failure the snapshot is restored in full (children, configuration, playback, and every presentation field) and a failure result is returned; nothing throws to the caller on any path (cloning, validation, fit, construction, snapshot, publication).
- Fit is gated at the effective mounted width: the minimum of the candidate's configured stage width and the mounted viewport width. Both the rebuild gate and the resize gate surface row-level fit diagnostics (figure id plus the failing quantity: required vs allocated, occupied vs available, budget, type floors) on the warning surface instead of a generic message.
- The restore set is derived mechanically from the presentation write set (the variables the presentation functions write); an own-check asserts the two sets are equal (44 = 44).

## Validation construction
- The validator carries a per-type schema table listing every field each renderer, state function, and geometry function reads, with a kind per field (string, array, fraction, positive, positive-integer, points). A schema pass generated from that table checks presence and kind domains for every figure.
- 38 timing keys carry domains derived from their consumers' arithmetic: fraction bounds for the draw/stack/bar ends, onset bounds in [0,1), positive spans and durations, exponent positivity, and the ordering relations the threshold and stamp-scale derivations assume. An empty points array and an empty bars array are named errors (an empty array draws nothing). The counter label opacity carries a 0..1 domain.
- Three keys are validation bounds rather than rendering consumers, classified as such in the census: two timing minima (each enforced against a derived duration — the summary typing duration, the fill duration) and a callout minimum clearance (enforced against the derived callout lane clearance).
- The fit report files an unresolvable figure record as a rejected row with its errors instead of dereferencing it.

## Presentation construction
- One emission table derives all 44 stage variables from the single configuration key set (palette, fonts, layout constants, computed layout); both presentation paths apply that emission and nothing else. The commit copy list and the rollback restore set are both derived from the same emission.
- The line chart's y-axis labels are placed from the same gap key the fit model reads for their extent. Measured pair behaviour: mutating the gap key 6 → 16 moves the mounted axis from x 61 to x 71 and holds the label-to-axis distance at exactly the key value at both settings (the axis pad absorbs the gap, so the governed quantity is the distance).
- Stylesheet literals outside the variable system are interface chrome only (controls, warning border/padding, dot radius), classified per-literal in the census leg.

## Mounted-layout derivation
- The org chart's connector endpoints are derived from the mounted row's layout: one function computes node centers from the same inputs the stylesheet cascade uses (content width, node count, node width, gap, space-around distribution); the geometry model exposes the centers per row and the builder draws to them. At 360 the first-row centers are 79.5 / 248.5. Builder-vs-derivation agreement is asserted in the suite; the independent comparison against browser-measured centers was not run (no browser route — see limitations).
- The stack figure's count row carries its line height explicitly, from the same key the model consumes for the counter height.
- The donut label is modelled at 54 px wide against a ring inner diameter of 46.4 px at phone height; the model flags this as an overflow risk. It is not asserted as fit; no rendered glyph measurement exists.
