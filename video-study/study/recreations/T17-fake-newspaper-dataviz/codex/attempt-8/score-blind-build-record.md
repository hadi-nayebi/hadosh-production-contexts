# T17 fake-newspaper dataviz — construction facts (neutral)

A single self-contained HTML file recreates a fake-newspaper animated dataviz: a broadsheet masthead, then six figures arriving in sequence on one stage — a line chart with a side card, a waffle chart with a typed summary card, a stacked-bars figure with a bar chart and donut, an org chart with a badge, a counter-and-graph collapse figure, and a correction figure with a stamp and margin notes. All construction is procedural from one configuration object; no specimen media, no external assets.

Construction facts a reviewer can verify in the source:

- Validation is shape-first: the configuration's figure collection is confirmed to be an array before any counting or iteration, every figure entry is type-guarded before any field read, and schedule endpoints (first and last figure) are guarded before dereference. Required palette members are enumerated by name — an empty or partial palette fails with the missing members named. A named maximum sample bound in the timing configuration caps the number of samples the counter renderer can generate over its window, so its per-frame loop is guaranteed to finish.
- The public rebuild entry validates its input inside its own failure boundary: a validation failure returns named errors through the same path as a construction failure, the incoming configuration is deep-copied before use (later mutation of the caller's object cannot reach the mounted scene), and a candidate that fails during construction leaves the previously mounted scene, its width styles, its page chrome and its playback state intact — including removal of any partially mounted figure roots.
- Remounting sizes the candidate from its own configuration: the stage-width variable is set from the candidate before the stage width is read, and page background and clock ink are applied by the same remount that applies the scene palette, not only at startup.
- The waffle figure's callout label sits in a dedicated lane below the dot grid, outside every dot row, with an arrow connector from the lane to its dot. A mounted census enumerates clearance pairs at several playback checkpoints at two phone widths: minimum clearance for label-to-marker pairs (the label against every dot, the summary block, and the figure title) and maximum endpoint gap for connector-to-anchor pairs (the arrow tip against its dot's edge).
- Each org-chart connector layer's height includes the span of the row margin below it, its strokes run the full layer height, and the report row itself carries no top margin — the mounted path from the CEO node to each report node is continuous. The same census asserts maximum endpoint gap for every connector line against both of its anchors, and the badge's clearance against the last report row.
- The fit report measures the widest occupied element per figure (including the widest single line of each figure title, and single-token content that cannot wrap) and reports that measured width against the available width; a single-token title wider than the content width reports not-ok with the occupied width named. Errors are retained for every figure identifier present in the configuration, whatever its shape, and global validation failures are included in the fit result's overall ok.
- The counter figure's vertical margins are configuration-owned: the mounted margin on the big counter element and the geometry model's card height consume the same value.
- Stage width has one owner: the controls bar width and both width fallbacks read the same configuration key through a stage-width variable; chart-title letter spacing and bottom margin, chart path stroke width, and counter-label letter spacing are each owned by one configuration key consumed by both the renderer and the geometry model.
- A stub-DOM mount harness executes the file's own builders and asserts mounted structure (parent and sibling order, emitted classes, mounted sizes, connector endpoints, clearance pairs) at 360px and 390px; a measured-fit leg and a configuration consumption census run on this same source. All geometry evidence is logic-level; no rendered-pixel verification exists for this build.
