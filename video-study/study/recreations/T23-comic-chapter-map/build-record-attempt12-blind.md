## Construction summary (technical facts only)

- Timeline: three appearances; per appearance approach 365 ms + dive 335 ms (cycle 2,100 ms, hold 0, pause 0). Filled counts 4 → 8 → 12; dive targets are panel indices 4, 8, 11.
- Resolved geometry: one record per (panel, appearance, width) computed by a single function; completion is the appearance being rendered; the completion bar and the completed-target mark strip are inside the record (the strip's height is added to the art origin and subtracted from the art height); detail selection reads the record's final height. The DOM refinement pass replaces only the record's band with the measured band and rebuilds a miniature when the refined detail class differs from the built class.
- Labels: the label decision is made once in the model (split, line count, size, fallback class are fields of the per-panel label record). The phone width chrome is derived from the tab's own horizontal padding tokens (5 + 6 = 11) by a validation guard that resets the token to the derived sum. One fraction token per regime is used by both the model and the DOM measurement check. DOM refinement renders the record's spans, counts rendered lines per span (a range over each span, internal wraps counted), and may accept the record, step the size down within the record's own split, or fall to the record's named fallback class. The model's initial decision and the measured final decision are recorded as separate fields. The header wrap-growth marker is reset at each layout pass.
- Validation: a frozen baseline object is generated mechanically from the final configuration (a generation step walks the final CONFIG and emits it; the own-check walk below verifies the key sets). Every reset path reads the generated baseline; no reset reads the editable configuration object. The mark strip field is range-validated (0–40) on intake and on restore.
- Resolution order: the final panel count and the final registry resolve before any dependent (appearances, panel bindings, fallback binding) is validated. A same-request registry conflict between the two registry routes follows a printed precedence: the first valid candidate stands; the second candidate is deferred and installed only if the first fails validation. A rejected registry replacement restores the prior working entry (re-validated against the active palette and ceilings); when neither the prior entry nor the default satisfies the active palette and ceilings, the replacement is refused and the prior entry stands, with a warning naming the refusal.
- Primitive kinds: a per-kind field contract table names each kind's required and numeric fields in renderer key names; validation dispatches field presence/type from the contract and the renderer renders under the same names. A graph primitive's node radius is optional under the contract; a graph without one renders at the configured fallback radius.
- Camera: approach and dive are poses of the same page wrapper (masthead + grid). The approach progress is remapped by an entry-progress token (0.25) and the approach easing has a non-zero initial slope, so the first applied pose is part-way along the path; the remapped progress reaches exactly 1 at the join, where the dive takes over the same wrapper. Every camera write (either phase) stores the elapsed value the pose was sampled at (phase start + in-phase sample) in one shared record; pause/resume re-bases from that record in both phases.
- Scheduler: last-applied phase is tracked separately from last-observed deadline; the deferred flush reconciles skip accounting against the applied phase. The pending deferred-apply record has one writer (the endpoint claim). The flush consumes the record's generation (a superseded generation that no resume re-queued is a logged no-op). The deferred-apply log entry carries measured values (flush elapsed, scheduled end elapsed, consumed phase). Release of a held cut clears any armed timeout before re-arming, leaving one timer chain.
- Policy tokens: duration ceilings live in a caps token group consumed by the clamps; breakpoint/gap/border ceilings live in the limits group; phone tab vertical padding is a layout token consumed by the label policy, the band height, and the DOM padding; the phone line limit's accepted range (1–3) is the splitter's reachable range. Scalar URL parsing derives integer/fraction types from the same field definitions the validator uses (a fractional field parses as a number on both routes).
