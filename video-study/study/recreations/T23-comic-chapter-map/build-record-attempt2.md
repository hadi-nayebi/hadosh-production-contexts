## Construction

One self-contained HTML file. A DOM grid page (cream comic page, header strip, numbered yellow-tabbed panels with code-drawn SVG miniatures) plays a looping sequence of appearances: each appearance fills more panels, holds, then the camera dives into the next chapter's panel, which takes over the frame. All variables live in one CONFIG object at the top of the script; URL parameters override them after strict validation. No specimen media, no traced assets, no captions/subtitles (header + tab titles are the technique's subject text).

### Named behaviors and constants
- **Label sizing (N1).** The tab label base size derives from the actual panel inner width: `base = clamp(panelInnerW × 0.14, 11, 18)` px. Tabs are `box-sizing: border-box` with `max-width: 100%`, so padding and border live inside the measured box. Overflow policy, in order: (1) single line, shrunk from the base toward the floor; (2) **two-line mode (primary readable policy)** — the number prefix stays on line 1 and the title balances across two lines, shrunk from the base toward the floor; (3) **number-only mode (fallback)** — engages only when two lines cannot fit at the floor. Named floor: **minimum readable label size 11 px**. Named fallback threshold: number-only engages when the tab-available width is below the width the balanced two-line form needs at 11 px (for the longest default title, whose balanced longest line is 12 glyphs: 12 × 0.52 × 11 + 14 ≈ **83 px** of tab width). A rendered-DOM refinement pass re-checks each tab's real scroll size and drops to number-only if a tab still overflows at the floor. Each tab records its mode, size, and base in `data-` attributes.
- **Header fitting (N5).** The header strip fits its text by shrinking from its width-derived base toward a named 10 px floor using the same glyph model.
- **Configuration, art registry, validation (N2).** Every layout constant lives in CONFIG: stage cap 960 px, header height factor 0.034 / minimum 18 px, header font factor 0.021, tab border 3 px, tab padding 1/5/6 px, tab placement (top/left/z-index), panel background, ghost glyph factor 0.30 and opacity 0.16, dive easing `cubic-bezier(.55,0,.85,.4)`, dive cover margin 1.03, fallback stage width 360 px, minimum panel width 48 px, typography (weights, letter-spacing, line height 1.25), the label model (base factor 0.14, max 18 px, floor 11 px, 0.52 em/glyph, 14 px chrome, separator, shrink step, number padding, generated-title prefix), and the art viewBox 160×100 with a named fallback art kind. Miniature art is a CONFIG **art registry**: each kind is data — a list of drawing primitives (rect / circle / line / polygon / path / text / grid / graph / circlesRow) with palette references (`$<palette-key>` for any palette key); a generic renderer serializes them, and all inscriptions are registry data fields. **All URL overrides are strictly parsed and normalized**: integers must match `^-?\d+$` and are range-clamped **with a named warning for every clamp, truncation, or discarded component**, numbers likewise, colors must be hex, a blank header falls back; nested groups are overridable via `?cfg:layout.<field>=…`, `?cfg:labels.<field>=…`, `?cfg:typography.<field>=…` plus `?fontFamily=…`, and nested values are range-validated with defaults restored on violation. Registry lookups use **own-property** checks and entry-schema validation (an entry must carry a primitives array; unsupported primitive types are dropped with a warning), so inherited object keys can never be mistaken for art kinds. Panel-count changes are guarded (1–24; appearances are re-validated against the panel list; dive targets clamp into range with warnings). All warnings are **visible on the surface**: a warning strip renders at the stage bottom listing `cfg._warnings`, and a geometry warning appears when the computed panel width falls below the configured minimum for the chosen columns/gap.
- **Dive behavior (N3).** The dive translates the target panel to the stage centre and scales it by `max(configured scale, stageW/innerW, stageH/innerH) × 1.03` computed from the panel's **inner art rectangle** (inside its border), so the miniature itself — not only its border box — covers the entire viewport at dive end (every viewport edge inside the inner rectangle's transformed bounds; the header and all neighboring panels are occluded). Panels are `box-sizing: border-box`, so the rendered panel box (border included) is exactly the geometry model's panel rectangle — the camera model and the rendered layout cannot drift apart. The dive target panel is rendered **filled** (its miniature shown) throughout its appearance — during the hold and at dive start, for every appearance; non-target panels keep their filled/ghost state. Visible filled totals per appearance are therefore **5 → 9 → 12** (configured counts 4 → 8 → 12 plus the target panel, which is the chapter about to play). Every phase entry establishes its own appearance and visibility independently (dwell, dive, and hold each render the due appearance and restore full opacity), so entering any phase directly — after a stall — shows the correct, visible state.
- **Schedule (N4).** Steps carry absolute start offsets; the cycle length is **derived** as the sum of the resolved schedule (default 5,850 ms). The engine derives the current phase from elapsed time on every tick (`phaseAt`: step, position inside the phase, remaining time, cycle index), so a stalled or backgrounded tab resumes at the phase actually due — expired phases are never replayed and cycle boundaries are crossed by the same derivation. A dive that starts late animates over the time **remaining** in its phase — recomputed after its render, immediately before the transition starts — arriving at the phase deadline; a dive entered directly (without its preceding dwell) first snaps the page to identity, so it never animates from a previous appearance's enlarged transform. Zero-duration steps are never selected by the phase derivation (they occupy no time interval), and a schedule whose four durations total zero is rejected at validation: the timing defaults are restored with a named warning. Pause freezes the active zoom transform where it stands and records the elapsed time; resume shifts the deadline origin by the paused duration, restores the frozen transform, and animates from it to the target over the remaining phase time.
- **Phase durations (defaults, with the tracker-reading reason).** dwell 900 ms · dive 650 ms · zoom hold 150 ms · dark pause 250 ms. Reason: with labels glance-readable in two-line mode at the 11 px floor and filled/ghost contrast carrying progress at a glance, the grid hold is priced as a flash-with-readability beat (the specimen's appearances are sub-second flashes) rather than a reading pause; the zoom hold is a brief settle only, because the dive target is already filled when the camera arrives; the dark pause is a short punctuation beat between appearances.
