## Construction notes (this attempt)
- Presented endpoint: when the tracked dive step's boundary is crossed, the engine first commits the endpoint transform as a presented state and defers the following step's apply to the next frame boundary — the endpoint is committed before reset in the presentation-order model (frame-boundary harness over the production transition code: the shipped tick / camera-loop / step-apply functions driven under a fake-DOM harness). Presentation is claimed per step under a single-winner rule across both callbacks; it occupies exactly one frame boundary, charged against the immediately following dwell; every phase deadline stays anchored to the absolute schedule (cycle origin + nominal offsets, 2,190 ms), so no drift accumulates. Late callbacks never accelerate, replay, or compress a phase: wholly-elapsed steps are logged as skipped (a skipped dive's endpoint is logged NOT PRESENTED), and the engine resumes in the phase containing the current absolute time. A pause mid-dive logs the step's disposition as not-presented; a presentation in progress survives pause as a state and re-derives its endpoint on resize. Painted-frame presentation is NOT VERIFIED (see Limitations) — no filing in this attempt claims a browser painted the endpoint.
- Validation order: resolution runs in three passes — every parsed override is validated and normalized BEFORE any generation consumes a value from it (generation dependencies and allocation limits are never read unvalidated); generation then consumes only validated values; the joint geometry feasibility restore/re-check runs over the resolved config. Generation-dependency guards (pad width, generated-title prefix, separator, label-policy group) sit before the registry and panel passes that consume them, and null/absent groups reset with named warnings before any group is read.
- Paint defaults: the paint contract is complete — a missing fill on any primitive kind resolves through the configured default fill; a missing stroke on a line and a missing edge stroke on a graph resolve through a new configured default stroke (both defaults are palette-token-capable and membership-checked at validation). An explicit fill of "none" in data remains expressible as data and is distinguished from missing.
- Scheduler: the emptied floor control is removed — the delay handed to the scheduler is the remaining time to the current step's end (the boundary guarantee is the engine's arithmetic, not a configurable floor), and an old URL naming the removed key warns as an unknown field. The former arithmetic presentation model is deleted; presented intervals are recorded by the presentation machinery's own logs.
- Shared resolved geometry: rendering produces one resolved-geometry record per layout pass — the modelled layout plus the refinement outcomes actually applied (measured header size; per-panel final tab mode/size and measured band height; the resulting art rectangle per panel). The camera endpoint derives from that record; the pre-refinement estimate only seeds the record. Resize re-runs the whole chain at preserved progress.
- Tab estimator: the width estimator now includes the configured tab letter spacing (the same term the header estimator already used), in the single-line and two-line paths, so the model and the DOM refinement start from the same width claim. Panel 07 at 360 px recomputes to two-line at 11.81 px under the corrected estimator (filed as computed in the fit table).
- Configuration surface: casing and whitespace are configuration — a title-case policy (preserve by default; the specimen's default titles are uppercase in the data itself) applies at validation, and panel titles supplied through the panels route are stored verbatim (the blank-slot warning still fires on an empty or all-whitespace slot). The label policy's maximum lines and fallback mode are validated configuration consumed by both the model policy and the DOM refinement. The art-defaults group is reachable through the nested override route, and a registry-map route supplies multiple art kinds in one URL as one JSON structure (the single-kind route is retained).
