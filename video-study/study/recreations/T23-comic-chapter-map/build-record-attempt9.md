## What the build is
A parameterized recreation of a comic chapter-map motif: a cream page of numbered, yellow-tabbed panels under a header strip; three appearances fill more panels (completed 4 → 8 → 12; the dive target also renders its miniature, so illustrated totals read 5 → 9 → 12); the camera moves continuously from the cut-in through the full-grid point and dives into the appearance's target panel until its miniature covers the viewport. All variables live in one CONFIG; URL overrides and direct CONFIG edits in source both resolve after strict validation with named warnings.

## Construction notes (this attempt)
- Continuous approach (no static dwell phase): the per-appearance timeline is approach → dive → hold → pause. The approach is a camera move: `approachTransformAt` interpolates scale from CONFIG `approachFromScale` (0.88) to identity at the full-grid waypoint under the configured easing; the transform changes in every sampled sub-interval, progress is monotonic, and scale/translation are continuous at the waypoint (approach end = dive start = identity, within solver precision ≈1e-7). Panel state (completed/illustrated counts) displays from each appearance's first frame exactly as before. `dwellMs` survives only as a deprecated URL alias that maps to `approachMs` with a named warning.
- Scheduler identity completeness: dive identity is the full triple (cycle, appearance, phase) in the camera claim comparison, the presented-keys record, and the pending-reset record. A dive that expires during its own entry render is logged skipped (endpoint NOT PRESENTED) through the same skip log, via the entry-render case. On resume, a pending presentation flushes before any step application — the resume path never ticks past a pending flush.
- Single resolved-geometry record under header growth: measured header growth produces one grown layout record (header height + stage height) that the resolved panel record, the camera endpoint, and the coverage calculation all consume; no consumer recomputes stage height from the original header height.
- Per-appearance chapter cut: every appearance's presented endpoint emits a chapter cut — CONFIG `cut.mode` (`signal` default; `hold` holds any appearance's endpoint until release), a per-appearance callback registration, and a readable `__t23Cut` state naming appearance, target panel, and endpoint key. Signal mode does not alter the absolute schedule. No scene content is built at the cut.
- Validation family (one construction): every registry/panel field validates its type before any coercion (an object-valued text `weight` drops the primitive with a warning; it cannot throw or bypass the warning strip). The path validator is a tokenizer that tracks separator placement and explicit signs: `M0,,0` and a bare leading `L10 10` reject with named warnings; `M+0 0 L1 1` accepts verbatim. Combination validation runs over the resolved configuration: a hold surface engaged with zero selectable dive phases warns and disengages; bezier control points whose y coordinates leave [0,1] reject with warning + default easing, and the camera interpolation clamps its fraction so interpolated scale stays finite and > 0. Joint width limits validate together (stageMaxPx below minStagePx restores both), and after any default-restore the feasibility recheck rebuilds its test regimes from the restored values. One normalization policy on every route: an out-of-range numeric installs the field DEFAULT (never a clamp artifact); token trimming is uniform; whitespace-only text is empty → named warning + default; `fontFamily` values with no letter characters reject with a named warning. Malformed values written directly into CONFIG in source pass through the same validation at startup (types and fallbacks come from an independent trusted-defaults record, never inferred from the edited values), with safe-integer and workload bounds applied before generation.
- Paint-default completeness + palette tokens: the stroke/fill default contract applies in every primitive branch (rect, circle, polygon, path, text) when the attribute is omitted; `none` is honoured as data. Every registry colour resolves through a palette token (`palette.art01`–`art41`), so a palette-only override recolors the miniatures. Validator and renderer share one primitive-kind table; unknown keys in structured panel objects warn by name.
- Parameterized layout surface: CONFIG gains `layout.paddingPx` (perimeter padding, split from the grid gutter `gapPx`), `layout.tabOverlapPx` + `layout.tabAnchor`, and `layout.pauseOpacity` — each consumed by the renderer, defaults equal to the previous fixed values. Tab labels: the label policy and the DOM refinement both receive panel number and title as separate values — neither splits an assembled label; the tab's lines are pre-split into separate DOM spans by the policy.
- Scale-adaptive miniatures: the art renderer selects a detail variant from the panel's rendered art height against CONFIG `artDetailMinPx`. Below the threshold, each kind renders its simplified variant: inscriptions smaller than the large-mark size are omitted as texture (the principal marks that must survive at phone scale are the large shapes and the one large inscription, `I KNEW IT!` at 24 units); graph edges double in width and nodes grow. At/above the threshold the detailed variant renders. Detail selection is LATCHED at render time for each panel — it does not change during a dive, because the art is not re-rendered mid-dive. The header gains a CONFIG break policy (`headerBreak`) consumed by its fit model and style. Completed panels carry a second distinction channel beyond tab colour: a CONFIG-palette completed-face tint on the panel face itself; an upcoming target never carries the completed treatment.
