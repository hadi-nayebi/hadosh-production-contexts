**Not ready to lift as-is.** The registry and count-derived layout provide a useful reusable base, but incomplete validation allows accepted overrides to hang rendering or break geometry. The build record overstates configuration coverage and safety.

1. **Critical — an override can hang the page.** `cfg:labels.shrinkStepPx=0` or a negative value passes validation. Both `labelPolicy()` and `headerFitPx()` can then loop indefinitely when text needs shrinking. Require a finite, strictly positive step. **Cost:** a production URL can freeze the surface before warnings become usable.

2. **High — most nested settings lack range or semantic validation.** Generic overrides accept negative header dimensions, padding, font factors, line heights, scheduling floors, and arbitrary typography values. `diveEasing` accepts any nonempty string, including invalid CSS. `maxPx < minPx` restores the default maximum without ensuring it exceeds the resolved minimum—for example, minimum 24 and maximum 8 become minimum 24 and maximum 18. **Cost:** silent styling rejection, clipping, inconsistent sizing, and altered scheduling; the claimed nested-validation guarantee does not hold.

3. **High — valid individual settings can produce invalid combined geometry.** At 360 px, `colsNarrow=6&gapPx=40` yields panels approximately 13.33 px wide. With the default 4 px border, their inner height is approximately 0.60 px; increasing `borderPx=12`, also accepted, makes inner dimensions negative. `computeLayout()` and `diveTransform()` proceed despite this. The minimum-width warning reports the problem but provides no safe fallback. **Cost:** broken panels and unreliable dive coverage under accepted configurations.

4. **Medium — configurable label settings are bypassed.** `render()` constructs labels with literal `" · "` instead of `cfg.labels.separator`; changing the separator therefore breaks `splitTwoLines()`’s parsing contract. The DOM refinement subtracts literal `0.5` instead of `cfg.labels.shrinkStepPx`. Number-only extraction uses literal whitespace splitting rather than the panel’s configured number. **Cost:** production label changes require renderer edits or produce inconsistent fitting.

5. **Medium — URL coverage and warnings are incomplete.** There are no override routes for panel numbers, registry entries, `artViewBox`, or `fallbackArtKind`. Unknown query keys are silently ignored. Empty `appearances=` is silently ignored; whitespace-only panel title slots can also be ignored without warning. Colors are validated after trimming but stored untrimmed, which can fail when used as palette values in SVG attributes. Out-of-range integers are clamped rather than restored to defaults. **Cost:** callers cannot rely on complete overrides or a uniform, visible fallback contract.

6. **Medium — registry extensibility works for compositions, not arbitrary new primitives.** A new art kind composed from supported primitives needs only a registry entry: this is a real strength. A new primitive requires changes to both `primKinds` and `primSVG()`. Existing primitive validation checks only type membership: missing graph nodes, invalid edge indices, empty grid fills, and malformed numeric fields remain unchecked. Null panel or appearance entries can also throw during validation. **Cost:** configuration authors can crash rendering; the registry is not yet a safely validated production interface.

7. **Medium — fallback behavior still reaches into global defaults.** `panelArtSVG()` uses `CONFIG.fallbackArtKind` rather than the resolved configuration’s fallback. Panel art references are checked before malformed registry entries are removed, and the fallback itself is not guaranteed valid. If every appearance is rejected, default appearances are restored **after** range validation without another pass against the current panel count. **Cost:** small custom panel sets can inherit invalid dive targets through the validator’s fallback path.

8. **Low — presentation literals remain outside CONFIG.** Warning-strip padding and stacking, SVG `preserveAspectRatio="none"`, and renderer stroke/text defaults remain hardcoded. Art colors are configurable within registry data, but changing `palette` alone does not retheme most miniatures. **Cost:** some restyling and art-fit changes still require implementation edits.

**Count and appearance scalability:** There is no fixed 12-panel or three-appearance loop in the core layout/timeline machinery. Nine or sixteen panels are structurally supported. Added panels receive placeholder titles and fallback art; they do not gain authored content or a newly derived appearance sequence automatically. The principal blockers are validation and configuration fidelity, rather than a hardcoded grid count.

SCORE: 62
