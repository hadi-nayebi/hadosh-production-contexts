# T54 — Map-as-table roster · neutral facts packet
Technique: a flat-color US map serves as the table; each member of an electorate is a circular chip placed on their home state with a name plate and, where relevant, an "Elect" tag; the camera zooms to the region under discussion; the full map appears when the roster completes. Packet evidence window: the technique runs 1:30–throughout the source video.

## Construction facts
- One self-contained HTML file; inline SVG: ground rect + one generated circle per abstract state blob (centre/radius anchors in CONFIG — generated arrangement, not traced boundaries) inside a single camera group; the camera is the SVG viewBox window computed from a keyframe track. A separate foreground group, drawn after all chip groups, carries every name plate and Elect tag.
- CONFIG-first: 78 top-level keys (roster, state anchors, palette, type sizes + a glyph-metrics table bound to the configured font family, camera primitives, pass regions, layout and search parameters, full-plate style tokens). All plate, tag and initials widths are computed from the single glyph-metrics table. The run duration is DERIVED, never stored.
- Segment state sequence (frames viewed at 5 fps): regional zoom at 1.0 s, widening underway at 1.2 s, full map settled at 2.0 s, full map still framed at 6.2 s, sideways pan underway at 6.4 s. Timeline as built (default roster): regional hold 0–1100 ms; interpolated move 1100–2000 ms; full map 2000–6000 ms; interpolated pan-away 6000–7000 ms (camera centre shifted by the configured exit shift, map leaving the frame); then a roster pass over five regions as a separately identified completion demonstration; then an interpolated return to the full view and a final full hold of 6600 ms. Derived total duration: 54400 ms.
- Placement: 55 chips place at a 34 ms cadence (placement ends 1870 ms); the effective pop duration is the configured pop scaled against the placement spacing (30.6 ms), so placement + pop settle complete at 1901 ms, before the 2000 ms full arrival. The full-roster count plate first appears at placement + pop settle, is hidden while the camera is away from the full view, and returns for the final hold. Its reserved strip is computed in code from its style tokens (38 units at default tokens).
- Roster pass: each region is visited in wave groups of at most four members; the camera frames each group (group bounds include Elect tag extents) and holds while that group's name plates show. Each wave's hold (dwell) is computed by a formula from the wave's name count and longest label, with a configured floor of 1200 ms; wave membership is driven by stationary-elapsed time, which accrues only while the camera is stationary. Name plates are hidden whenever the camera is moving; at a stationary beat each plate takes the first collision-free position from an obstacle-scored candidate search (obstacles: every placed chip's disc and every Elect tag); a plate with no collision-free position at a beat is hidden at that beat.
- Final hold: at the full view, name plates cycle in index groups of five members, 600 ms per group, covering all 55 identities across the hold.
- Chips are generated initials discs (never portraits), radius 9 units. Same-state positions are generated by a deterministic golden-angle spiral. A deterministic relaxation pass separates all disc pairs to at least the configured centre distance (measured minimum 22.0 units); any chip displaced beyond the configured threshold from its home anchor carries a thin connector line to that anchor, drawn outside the pop-scaled group; connector endpoints are a pure function of anchor and laid position. Initials are extracted as grapheme clusters (a locale-configured segmenter), so decomposed accents and supplementary-plane letters stay whole.
- Elect tags are positioned by a scored search that avoids every other chip's initials bounds and every other tag; all ten tags hold a collision-free position. Name plates at stationary beats are verified pairwise disjoint and disjoint from every placed disc and tag, inside the camera window.
- Validation runs before any DOM construction and rejects, with field-specific errors: duplicate or unknown state ids, chips referencing unknown states, per-state capacity overflow, pass-region coverage gaps, an opening region or pass region with no roster members, nonpositive or non-finite durations, a zero tag grid step, a font family with no matching glyph-metrics profile, a derived wave dwell that is not positive, and a placement schedule whose end + pop settle would overrun the full arrival. A layout-feasibility result (minimum centre distance, tag fallbacks, displayed-plate collisions, identity exposure coverage) is computed for the final layout and reported as validation errors when it fails; on the default roster it passes with every identity displayed at one or more stationary beats.
