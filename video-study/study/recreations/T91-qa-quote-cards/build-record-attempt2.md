### List replacement, validation, fit contract
- **Replacement:** an override carrying `cardsReplace: [...]` — or `schedule.replaceCards: true` together with a `cards` array — replaces the card list wholesale; the default per-index patch behaviour is unchanged otherwise. Verified: 1 card → cycle 5600 (uniform), 2 → 9800, 4 → 18200, each rendering exactly the supplied count. An empty list under replacement semantics is invalid (validation error), never a silent restore and never a blank stage.
- **Validation before first paint:** malformed override JSON, a non-object override, empty/missing card fields, a non-integer year, non-finite or non-positive timings, a non-hex palette value, non-positive geometry, an out-of-range specimen index, entrance ≥ any sequence slot, exit ≥ any sequence slot, or reveal + minimum hold + exit beyond any sequence slot each produce a visible error state naming the offending key/index and the expectation, expose the list on window.__t91.errors, and render no schedule. Unknown top-level override keys are collected as warnings on the same surface.
- **Fit contract (deterministic, ordered):** shrink the quote size in 1px steps down to the 20px floor until the quote block fits the quote zone; if it still does not fit at the floor, validation error naming the card index and the overflow in px — never silent clipping, never overlap with the attribution. Speaker exactly 1 line; role at most 4 lines with the attribution block inside geom.attrH (see deviation D-T91-1). Fitting and rendering share one font-metric basis: in the browser, canvas measurements in the rendered font string; in the harness, the PIL stand-in tables for the same stack.
