Today's study went back over the publish-package rules — the checklist every video package is built and checked against — and compared them with the scoreboard rules that were tightened yesterday.

Four places disagreed. The package standard's final section still described the scoreboard duties in the old, simpler form. The distribution defaults — the short list a publisher actually follows two days after a publish — did not mention the scoreboard duties at all. The decision model's packaging section pointed at neither. And inside the QC checklist itself, one summary line still described the completeness rule as if it were only about coverage, when the rule itself now has three parts: coverage, the re-read ladder's state, and what was done about any spike.

All four now say the same thing, in the same words, and each one points at the others. One newer rule — recording where a dip or spike falls inside a container-built video — is still marked provisional everywhere it is named, because no published video of that kind has a readable curve yet; the first one that does is where it gets its first real test.

Checked against the three real scoreboards on file: each one exists (coverage is fine), and each one is still missing its ladder state — that gap is now named by the package rules themselves instead of sitting silent, and it is carried to the next scoreboard round.
